# Handoffs and relay

`src/handoff.ts` (store), `src/handoff-cli.ts` (`enigma handoff`, `__handoff-hook`), `src/handoff-deploy.ts` (wiring), `src/relay.ts` (`enigma relay`), `assets/mods/enigma-relay` (Claude Code mod), `assets/commands/handoff.md` (`/handoff`). Settings: `relay` (on), `relay-at` (300k, global).

- WHY: every call re-reads the conversation; clearing is the cheapest reset but forgets the task. A handoff page bridges the clear. Same shape as the Ralph loops (snarktank/ralph, open-ralph-wiggum) and the Claude handoff hooks (set-claude-handoff, cc-clear-handoff).
- STORE: one handoff per project (git root), `~/.enigma/handoff/<sha1(root)>.md` + `.json` (savedAt, consumedAt, done), outside the repo. Delivered ONCE (consumedAt), never when `STATUS: done` or older than a day. 32 KB cap. `latest.json` points at the newest save for the mod, which has no shell and no hashing.
- DELIVERY is one runtime (`__handoff-hook <host>`) for every host with a session-start event, only on a fresh context (`startup`, `clear`; never `resume`/`compact`, which keep history): JSON `hookSpecificOutput.additionalContext` for Claude and Codex, plain stdout for Kimi Code. Codex hooks.json has Claude's settings shape, so `applyClaudeHook` merges it; written only where ~/.codex exists. Kimi Code sources are `startup`/`resume` (no `clear`). OpenCode: a plugin on `session.created` posts it with `client.session.prompt({ noReply: true })` - written from the docs, NOT run end to end (OpenCode not installed here).
- AUTOMATIC RELAY (Claude Code only): no host lets a hook clear its session (Claude's hooks reference says so; Codex's and Kimi's too). Claude Code's function-hook mods can: `$.session.usage()`, `$.command.run({ command: "clear" })`, `$.prompt.submit()`. The mod, on `turn.complete` of the main loop past RELAY_AT: submit "run /handoff"; on the next turn's end, if latest.json shows a save newer than the ask for this project, run /clear and submit "continue" (with the page inline when the session-start hook did not already deliver it). Never clears without a saved handoff; `STATUS: done` stops; 20 relays per session max. A relay that kept the context (nothing saved, or done) is not asked again until the context grows by another RELAY_AT/2, or drops back under RELAY_AT first. Installed by copying the asset to ~/.enigma/claude-mods/enigma-relay with RELAY_AT and the pointer path substituted, and naming that folder in settings `env.CLAUDE_CODE_PLUGIN_DIRS` (other folders kept). Mod APIs are EARLY ACCESS: `claude plugin validate` and `claude plugin test` pass on 2.1.290 (3 tests in the asset's tests/), but the loop was not run in an interactive session.
- `enigma relay`: the cross-host automatic version - a loop of fresh headless sessions (`claude -p` - bypass, or `acceptEdits` plus `--allowedTools "Bash(enigma handoff save:*)"`; `codex exec --sandbox workspace-write -c sandbox_workspace_write.writable_roots=['<handoff dir>']`, since the store is outside the workspace; `opencode run`, Kimi Code `kimi -p`; Kimi refuses `--auto` beside `-p`). The prompt goes in a file the agent is told to read, never on a cmd.exe line. Stops on STATUS: done, on a step that saved no handoff, or at --max. Steps run with `ENIGMA_RELAY_STEP=1`, and the session-start hook delivers nothing there: an older pending handoff must not steer (or be spent on) a relay step. `env: process.env` is passed explicitly: Bun does not give a child the variables changed at run time otherwise (found by the test). Verified end to end with Claude (one step, file created, done).
