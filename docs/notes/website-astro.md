# Website is an Astro + MDX app (`apps/web`), NOT hand-written HTML

- `apps/web` was migrated from two hand-written static files (`index.html`, `docs.html`, vendored `lib/fuse.min.js`) to an **Astro 7 + @astrojs/mdx** project that builds to static HTML. DO NOT recreate or edit raw `.html` in `apps/web` - author content as `.astro`/`.mdx`. STANDALONE package (`@enigmax/web`, private, NOT in the root `workspaces` which is `packages/*` only) with its OWN `package-lock.json`; CI builds it independently (`cd apps/web && npm ci && npm run build`). Requires **Node >= 22.12** (Astro 7), so `pages.yml` pins `setup-node@22` - the root repo's `engines` stays `>=18` and is unaffected because apps/web is not a workspace.
- BASE PATH: GitHub Pages serves the site at `https://fjrg2007.github.io/enigma/` (project subpath, no custom domain - verified via `gh api repos/.../pages`, `cname:null`). So `astro.config.mjs` sets `base: "/enigma"`. Astro base-prefixes its OWN bundle/asset URLs, but NOT hand-written links - so all internal links + public assets go through `src/lib/url.ts` (`url(path)` / `docHref(slug, anchor)`), which normalizes `import.meta.env.BASE_URL` to a single trailing slash (BASE_URL came back as `/enigma` WITHOUT a slash - joining naively produced `/enigmadocs/...`; the regex `replace(/\/?$/,"/")` fixes it). If you add a link or asset reference, route it through `url()`/`docHref()` or it breaks under the subpath.
- SOURCE LINK: a component page's "source" link comes from the registry (`src/lib/registry.ts` -> the item's `source` field), never from the page's slug. The slug is not the file name: `video` is `core/player.ts`, `image` is `core/image-viewer.ts`, `toast` is a renderer over `core/notifications.ts`, and `notifications` moved package. Building the path from the slug linked several pages at files that do not exist, and it failed silently because nobody clicks their own footer. `packages/primitives/test/registry.test.mjs` asserts every `source` is a file that is really there.
- ASSETS: brand logos + dashboard.png are NOT duplicated in the app - `scripts/sync-assets.mjs` (predev/prebuild) copies `<repo>/assets/logos/*` and `assets/images/dashboard.png` into `apps/web/public/` (gitignored: `public/logos/`, `public/dashboard.png`). Single source of truth stays `<repo>/assets`. `assets` already ships nothing here; the copy runs at build only.
- DOCS: MDX content collection in `src/content/docs/*.mdx` (`src/content.config.ts`, glob loader, schema `{title, description, group, order}`); entry id (filename w/o ext) = route slug. Routes: `src/pages/docs/[...slug].astro` renders each doc inside `DocsLayout.astro`; `src/pages/docs/index.astro` redirects to `getting-started`. Reusable `Cmd.astro` component (~12 uses) replaces the repeated command-card markup; terminal snippets are fenced code blocks (Shiki, theme `vesper`, bg overridden to `--surface`) so they get the copy button. The config table stays raw HTML inside the MDX (entities `&lt;`/`&gt;` required - rehype-raw would drop literal `<usd>` tags).
- SEARCH = command palette (the old `lib/fuse.min.js` 404'd because `pages.yml` never copied `apps/web/lib/` - the whole reason for this migration). `src/lib/search.ts` builds the index at BUILD time from the content collection (`render()` headings + `entry.body`, markdown/MDX stripped to prose snippets); `CommandPalette.astro` serializes it into a `<script type="application/json">` and a bundled module runs Fuse over it - centered modal, blur backdrop, real-time results, keyboard nav, `Cmd/Ctrl+K` + `[data-search-open]` triggers. Fuse is bundled into `_astro/*.js` (no separate file to 404).
- COPY BUTTONS: a client script in `DocsLayout.astro` adds a hover-reveal copy button to every `.doc pre`, using `navigator.clipboard.writeText` with a synchronous `document.execCommand("copy")` FALLBACK (covers a browser clipboard-guard extension that breaks `clipboard.writeText` - that injected `clipboard-protection.js` is NOT ours). The landing install-block copy uses the same fallback.
- To add a doc: drop a `.mdx` in `src/content/docs/` with frontmatter; it auto-appears in the sidebar (by `order`) and the search index. To deploy: push to main touching `apps/web/**` (pages.yml). DO NOT add `apps/web` to root workspaces (keeps Astro's ~313 deps off the CLI install).

## The docs palette runs on the package the site documents

`CommandPalette.astro` keeps its hand-written DOM and takes its BRAINS from
`@enigmax/primitives`: `createSearch` (with Fuse handed in), `moveActive`, `groupRows`,
`createRecentStore` and `isPaletteShortcut`.

The DOM stays hand-written on purpose. `SearchPalette` is React, and mounting a React island
on every docs page to replace a working dialog would charge every reader the framework for
one panel - the opposite of what the package is for. What is shared is the part that has no
framework in it at all, which is also the part that was duplicated: the keyboard arithmetic,
the grouping, and the history the site did not have before and now does.

That split is the rule for dogfooding here: take the core, not the renderer, wherever the
surrounding page is not already React.
