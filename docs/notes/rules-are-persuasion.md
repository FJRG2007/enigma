# Rules are persuasion, not enforcement (enterprise)

- Skills/memory only persuade the model; for real safety, back critical rules with deterministic gates: Claude Code hooks (settings.json), pre-commit hooks (gitleaks, lint-staged, typecheck), and CI (lint, typecheck, tests, `npm audit`/SAST). security-policy and dependency-policy each end with a "make it mechanical" section pointing at these gates.
- Deterministic gates (tooling distributor, no app test suite): `npm run check` (syntax + skills sealed, catching silent seal-drift), `npm run guard` (`src/guard.ts --all` via tsx: secrets, .env, node_modules), `npm run verify` (typecheck + check + guard). CI: `.github/workflows/ci.yml`. Auto-publish to npm: `.github/workflows/publish.yml` (on GitHub Release; needs `NPM_TOKEN`, checks tag==version). This repo's pre-commit: `.githooks/pre-commit` (`git config core.hooksPath .githooks`).
- CIPHERA-STYLE GATE (changed-LINES ratchet). The Ciphera style skill is persuasion-only and gets skipped; the deterministic backstop is `@enigmax/linter` (already in-repo, AST-accurate, parses `.astro`/`.vue`/`.svelte`/`.ipynb`). WHY changed-LINES not changed-FILES: the repo carries ~142 pre-existing style warnings, so a file-level gate would block almost every commit on unrelated legacy findings and train everyone to `--no-verify`. `scripts/lint-changed.mjs` (run via tsx, imports the linter's `lintFiles` API) intersects the linter's findings with the ADDED/MODIFIED line numbers from `git diff -U0` and fails on ANY finding that lands on a changed line (severity-agnostic - style WARNINGS block too, which the CLI's default error-only exit would not). Modes: `--staged` (pre-commit) and `--range <a...b>` (CI). Wiring: root script `lint:changed` = `tsx scripts/lint-changed.mjs`; `.githooks/pre-commit` runs the guard THEN `npm run -s lint:changed -- --staged`; CI `linter` job (`fetch-depth: 0`) computes the PR/push range and runs `lint:changed -- --range "$range"`. The CLI also gained a standalone `--strict` flag (fail on warnings too, not just errors; linter `0.4.1`) used by the skill's self-check fallback, not by the line-gate. GOTCHA: `npm run lint` = `npm run -w @enigmax/linter dev --` cd's INTO the linter package, so repo-relative paths passed to it silently resolve to nothing ("no problems found" = a false pass); run from repo root (`lint:changed`, or absolute paths) instead. The ciphera SKILL.md gained a "Self-Check (Before Declaring Done)" line pointing at `npm run lint` / `lint:changed` / `npx @enigmax/linter --strict`. To make the gate whole-repo blocking later, fix the backlog first (`npx tsx packages/linter/src/cli.ts packages apps`), then add a whole-repo `--strict` lint to `verify`.
- `src/guard.ts` is a self-contained (Node-builtins-only) commit guard: it is BOTH this repo's CI/hook scanner (run via tsx, or as built `dist/guard.js`) AND the engine `enigma security` copies into any target repo (`setupGitHooks` in `src/security.ts` copies the guard to `<repo>/.githooks/guard.mjs` and writes `pre-commit` + `enigma-guard.json`, then sets `core.hooksPath`). It locates the guard via `ENIGMA_GUARD_PATH` (set by the launcher) -> `dist/guard.js`. Keep it dependency-free and free of cross-module imports (tsup bundles it standalone). Its module footer self-executes only when `argv[1]` basename matches `guard.*`, so the copy inlined into the compiled binary stays inert. Protections toggleable via `enigma-guard.json`; env allowlist = example/sample/template. Hooks also cover GitHub CLI (`gh`) commits, since gh uses git.
- GitHub repo: `https://github.com/FJRG2007/enigma.git` (renamed from `.../ai.git`). npm package: `enigma-cli` (command `enigma`); license Apache-2.0. Package name was previously `@tpeoficial/skills` then `@fjrg2007/ai`.
- CONTEXT COST IS A GATE TOO. `enigma check` fails when a bundled memory file (`assets/memory/*.md`) exceeds `MEMORY_BUDGET_BYTES` (24 KB, skills.ts), and the `ctx-memory-budget` guardrail blocks an edit to any `CLAUDE.md`/`AGENTS.md` over 40 KB. Both exist because "keep the always-on channel small" was doctrine long before it was enforced, and the repo's own `CLAUDE.md` still reached 215 KB. The structural fix is the same one the rule's message prescribes: `CLAUDE.md` is an INDEX (12 KB budget) and every subsystem's detail lives in `docs/notes/<topic>.md`, read on demand.
