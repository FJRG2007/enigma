# Dashboard exposure: bind modes + token auth (the openclaw model)

- WHY: `enigma dash` on a headless server CRASHED (`spawn xdg-open` ENOENT), and even fixed, a loopback dashboard is unreachable there. Ported OpenClaw's gateway model (researched from docs.openclaw.ai; no repo clone) rather than inventing one.
- THE openUrl CRASH IS AN ASYNC-EVENT BUG, not a missing try/catch. Bun/Node emit a spawn ENOENT as an ASYNCHRONOUS `error` event on the child; an EventEmitter with no `error` listener rethrows it as an uncaught exception, so the surrounding try/catch CANNOT see it (the stack still points at the `spawn` callsite, which makes it look synchronous - that misleads). Fix = `child.on("error", ...)`, plus `isHeadless()` (no DISPLAY/WAYLAND_DISPLAY on non-win/mac) to skip the spawn entirely. Same bug/fix in `scripts/dashboard-preview.mjs`. Any future detached `spawn` MUST attach an error listener.
- MODEL (`dashboardBind`: loopback|lan|custom + `dashboardBindAddress`): CORE RULE, ported verbatim - a non-loopback bind REFUSES TO START without a token (`resolveBind()` throws). The dashboard is an admin surface (playground runs agents with the user's creds, resources kills processes, config-import writes config), so unauthenticated exposure is never an option, only fail-closed. No `tailnet` mode (no tailscale integration; `custom` pins a tailnet IP).
- TOKEN lives in `~/.enigma/dashboard-token` (0600) + `ENIGMA_DASHBOARD_TOKEN`, NOT in `.enigma.json` - DELIBERATE DIVERGENCE from OpenClaw (which uses `gateway.auth.token`): this repo's `.enigma.json` is deliberately committable, so a token there would land in git. Env wins and is never rotated/overwritten (owned by whoever injected it). `tokenMatches` sha256-hashes both sides before `timingSafeEqual` so no length short-circuit leaks the length.
- FRAGMENT BOOTSTRAP (ported faithfully): the link is `.../#token=...`, NOT a query string - a fragment is never sent to the server, so it cannot reach an access log or Referer. `packages/dashboard/assets/index.html` has a CLASSIC (non-module, so it runs before the deferred module) script that reads `location.hash` -> `sessionStorage` keyed by origin (not localStorage) -> `history.replaceState` strips it -> wraps `window.fetch` ONCE to add `Authorization: Bearer` to every `/api/*` call. The wrapper is the only sane option: there are ~51 bare `fetch("/api/...")` call sites. It is installed even WITHOUT a token so a 401 still raises the "needs a token" banner - else an exposed dashboard opened without its token renders ~20 silently empty panels.
- AUTH GATE is ONE check at the top of `createDashboardServer`'s handler covering all `/api/*`, and it is the ONLY one: `isAuthorized` is now the sole caller of `isLocalRequest`. The per-route `isLocalRequest` guards were DELETED - do NOT re-add them. `isLocalRequest` requires Host to be in LOCAL_HOSTS (enigma/localhost/127.0.0.1/::1), which an EXPOSED dashboard never sees, so a per-route guard 403s ~20 routes (settings/skills/memory/accounts/packs/playground/recall/projects/resources/plan/config-import) for a browser holding a valid bearer - and the HTML banner only fires on 401, so the user just sees silently empty panels. `isAuthorized` already covers both binds: loopback -> the Host/Origin allowlist (`isLocalRequest`); exposed -> Origin==Host (an allowlist would break real setups) + the bearer. NOTE the gate also CLOSED a pre-existing hole: `/api/stats|status|provider-status` had NO guard at all, so DNS-rebinding could read costs/projects/sessions from a loopback dashboard. `/` and `/lib/*` stay open (static, no data, and the page must load to run the bootstrap).
- SURFACES: `enigma dashboard --expose` (this run only, no persist - the "solo esta vez"), the headless TTY prompt in `resolveHeadlessBind` (keep local / once / always; "always" persists `dashboardBind=lan` and is what stops it re-asking), `enigma dashboard token [--new]`, `enigma config dashboard-bind[-address]`. `--new` had to be added to parseArgs (unknown options are rejected BEFORE the subcommand runs) and owns its own `opts.newToken` field - deliberately NOT folded onto `opts.force`, which is global, so aliasing them would have made `--new` an undocumented `--force` on every other command. dashboard-bind is CLI-only (NOT in the settings registry): it is a 3-value choice with no "off" value, and exposing an admin surface should not be a switch inside the very web UI it exposes.
- BIND ERRORS CANNOT BE DIAGNOSED FROM THE ERROR CODE (verified on both runtimes). bun flattens EVERY `server.listen` failure to `EADDRINUSE` with the message "Failed to start server. Is port X in use?" - including an unroutable address (192.0.2.1) and an unresolvable hostname - where node correctly reports `EADDRNOTAVAIL`/`ENOTFOUND`. enigma SHIPS as a bun binary, so the misleading code is the one users hit, and any `catch (e) { if (e.code === ...) }` port/host discrimination silently does nothing in production while passing under tsx. `listenWithFallback` instead infers it structurally: the candidate list always ends at port 0, the OS always has a free ephemeral port, so exhausting the list means the INTERFACE is unavailable (stale `dashboardBindAddress`, downed tailnet), not the port - and the error says so. `dashboard-bind-address` is also validated on write (`isIP` + a hostname regex in settings.ts), which catches typos where the address is still in hand.
- GOTCHAS when verifying by hand: (1) `dashboardAssetsDir()` prefers the MANAGED install (`~/.enigma/dashboard/...`) over the dev workspace, so a dev run silently serves the PUBLISHED bundle - set `ENIGMA_DASHBOARD_ASSETS` to `packages/dashboard/assets` or you test the old UI; (2) `daemonFile()` uses `homedir()`, NOT `enigmaHome()`, so `ENIGMA_CONFIG_HOME` alone does NOT isolate the daemon record - set HOME/USERPROFILE too or a live daemon makes the run print "already running" and defer.
- TESTS: `tests/dashboard-expose.test.ts` (in ci.yml). It binds mode `custom` pinned to `127.0.0.1` - token enforcement keys off the bind MODE, not the address, so the whole auth path is exercised WITHOUT ever putting a port on the network of the machine running the suite. The 0600 assertion is `test.skipIf(win32)` (chmod is a no-op on Windows).
- `hostOnly` MUST take a bracketed IPv6 literal whole. Host/Origin deliver IPv6 as `[::1]:24282`; the original `.split(":")[0]` cut `[::1]` to `""` (a loopback dashboard 403'd its own IPv6 client - page loads, every panel silently empty) and `[2a01:db8::1]` to `2a01` (addresses sharing a first group compared equal, weakening the exposed bind's Origin==Host check). Regression test drives the real server via raw `node:http` - `fetch` rewrites Host to the address it dialed, so it CANNOT test this.
