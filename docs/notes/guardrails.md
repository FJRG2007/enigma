# Guardrails: deterministic convention enforcement (`src/guardrails.ts` + post-edit hook + commit backstop)

- WHAT/WHY: the deterministic-gate answer to "skills get skipped so conventions (UUID keys, Prisma-for-TS) are not applied". A DATA-DRIVEN rule engine runs as a post-edit hook: after an agent writes a file, matching rules scan it and a BLOCK violation is fed back (exit 2 + stderr) so the model self-corrects in the same turn - zero model tokens until a violation. Adding a rule = one data entry (built-in array or `~/.enigma-guardrails.json`), never code. This is the CONVENTION twin of the auto-lint (`lint.ts`) STYLE hook and reuses that exact delivery channel. Config `guardrails` (config.ts), default ON/opt-out (a baseline enigma behavior, unlike the opt-in `autoLint`/`compress`). Decisions (user): name `guardrails`, default ON, scope Claude + OpenCode + commit/CI backstop.
- ENGINE `src/guardrails.ts` is SELF-CONTAINED (Node-builtins only, NO enigma imports) exactly like `guard.ts`: BOTH bundled into the CLI (cli.ts imports `runGuardrailsHook` for the hidden `__guardrails-hook` command) AND built to `dist/guardrails.js` (tsup entry) copied standalone into a repo's `.githooks/guardrails.mjs` as a commit/CI backstop. Self-exec footer guarded by basename `/(^|[\\/])guardrails\.[mc]?[jt]s$/` so the bundled copy stays inert (same reason as guard.ts). `globToRegExp` is DUPLICATED from guard.ts (marked `enigma:`) to stay import-free. `GuardrailRule = {id,label,files[](globs),scope:"file"|"project",pattern?(regex src),flags?,check?(project-check id),message,severity:"block"|"warn",skill?}`; `Finding`. `checkFile(file,content,projectRoot)` runs file-scope regex rules (line-by-line, non-global regex) + project-scope checks; `PROJECT_CHECKS` (coded, keyed by `check` id - NOT user-authorable, needs logic) has `ts-relational-no-prisma`. `loadRules()` = `BUILTIN_RULES` minus `disabled` + custom `rules`, read INDEPENDENTLY from `~/.enigma-guardrails.json` (ENIGMA_GUARDRAILS_CONFIG relocates it - REQUIRED for tests, else they pollute the real `~/.enigma-guardrails.json` via homedir(), the github.test lesson). `runGuardrailsHook()` reads the Claude/opencode PostToolUse payload from stdin (`tool_input.file_path`), block->stderr+exit 2, warn->stdout+exit 0. `runGuardrailsScanCli(all)` = standalone git scan (full-file, NO changed-line intersection - matches guard.ts precedent; the plan's changed-line idea was dropped as over-engineering).
- RULE MODEL EXTENSIONS. `absent?: string`: a file-scope rule fires ONLY when `pattern` matches AND `absent` does NOT match anywhere in the file ("X without Y") - how "reads request input WITHOUT a schema" is detected; the absent set is deliberately BROAD (every common validator) so precision > recall. `excludeFiles?: string[]`: globs that exclude a file even when `files` matches (used to exclude test files from the backend rules). `flags` uses `?? "i"` (nullish) so an explicit `flags: ""` means case-SENSITIVE (needed to tell a lowercase DOM `<input>` from a capitalized `<Input>` component); undefined -> "i". checkFile SKIPS comment lines (`COMMENT_LINE` = `//`|`#`|`*`|`--`|`<!--`|`{/*`) so a pattern mentioned in a comment never false-positives.
- SEED RULES (6). Two DB (`db-uuid-pk` block, `db-ts-orm-prisma` warn) + four convention rules for the "validate every input / reusable components / no cutre native dialogs" asks (generic principle, tool-per-language): `be-validate-input-ts` (warn, `*.ts/js/mts/cts`, exclude tests), `be-validate-input-py` (warn, `*.py`, exclude tests), `fe-password-input` (warn, `*.tsx/jsx`, `flags:""` case-sensitive `<input ...type="password">`, absent = password-toggle state vars), `fe-no-native-dialog` (warn, `*.tsx/jsx/ts/js/mts/cts/vue/svelte/astro`, exclude tests, `flags:""` case-sensitive). ALL warn (advisory, never block). The native-dialog rule pattern `\bwindow\.(alert|confirm|prompt)\s*\(|(?<![.\w])(alert|confirm|prompt)\s*\(\s*["']` = window.* (unambiguously browser, no FP in a Node file) OR a bare alert/confirm/prompt with a STRING-LITERAL arg only (a native dialog takes a string; CLI libs clack/inquirer and custom design-system dialogs take a `{config}` object; an AI `prompt` is a string that is passed, not called with a string literal). `(?<![.\w])` lookbehind excludes method calls (`toast.alert(`, `p.confirm(`) and identifier suffixes (`renderPrompt(`); case-sensitive excludes capitalized customs (`<Alert>`, `Confirm()`). Verified 0 FP on enigma (clack `p.confirm`), the CLI reference repos (inquirer/clack object-arg), and AI repos (bare `prompt` variables); the only wild hits were 2 real TPs in claude-mem (a `confirm('...')` in a React LogsModal + its minified bundle). PRECISION HARDENING (the "asegurate de que no de falsos positivos" pass, validated by scanning ~1700 files of real reference repos): the be-validate rules match ONLY the ASSIGNMENT of the request BODY (`=\s*req.body`|`=\s*(await )?request.json()`|`=\s*ctx.request.body`|`=\s*await c.req.json(` for TS; `=\s*request.get_json(`|`.form`|`.POST`|`request.json` for py) - NOT `req.query`/`req.params` (single scalars, validated inline) and NOT a body passed as a bare arg (e.g. `summarizeRequestBody(..., req.body)` to a logger), which were the real-world FP sources found in claude-mem. `absent` is broad (TS: z.|.parse(|.safeParse(|.validate(|.assert(|valibot|yup|joi|ajv|superstruct|typebox|@sinclair|arktype|io-ts|runtypes|@Body(|class-validator|express-validator|checkSchema|celebrate; py: BaseModel|pydantic|marshmallow|serializers|TypeAdapter|field_validator|model_validate|is_valid(|forms.|ModelForm|cerberus|voluptuous|jsonschema|@dataclass|.load(|Schema(). Result: 0 findings on the FastAPI wrapper / headroom(1001) / helio / autoskills / caveman; the only wild findings were 3 db-ts-orm-prisma on claude-mem (TS+SQLite/Postgres, no Prisma - correct opinionated warn). Go AND Rust deliberately SKIPPED for input-validation: Go's manual validation (`if in.X == ""`) is idiomatic with no detectable signature, Rust's serde typed deserialization already enforces shape - a rule for either would false-positive (honors "los que detecte con precision"). Stack-specific optimistic-UI/caching heuristics (TanStack useMutation-sin-onMutate) were NOT added as rules - they belong to the memory kernel (semantic, no reliable signature).
- AI CHAT UI -> AI ELEMENTS (`fe-ai-elements-chat`, warn). Vercel's AI Elements (elements.ai-sdk.dev, Apache-2.0, npm `ai-elements`) is a shadcn/ui REGISTRY, not a runtime dep: `npx ai-elements@latest add <c>` copies the source into `@/components/ai-elements/`, which is why it fits dependency-policy's vendoring preference rather than needing a dependency justification. Routed as TIER 2 (domain skill only): the detail lives in frontend-policy's "AI Chat & Agent Interfaces" section and is deliberately NOT in the memory kernel - it only matters when building React chat UI, so the always-on channel would pay for it every session (the scalability rule above). PRECISION: the rule keys on `.role === "assistant"` in `*.tsx`/`*.jsx` ONLY. Matching `"user"` was rejected after measuring a real multi-repo corpus - `user`/`admin`/`owner`/`member` are the RBAC vocabulary (95 hits, all permission checks) while `assistant` has no meaning outside an LLM conversation (17 hits across 15 files, ALL genuine chat surfaces, 0 FP). `absent` clears the file when AI Elements or another kit (assistant-ui, copilotkit, nlux, chatscope) is already imported. The test asserts the RBAC non-match, and that assertion was verified load-bearing by widening the pattern and watching it fail. React-only by nature, so the skill states the boundary: on Vue/Svelte/RN/plain HTML build natively and borrow the composition model instead of bolting on Tailwind+shadcn.
- NO TYPOGRAPHIC DASH IN UI COPY (`ui-no-em-dash`, BLOCK) + VISUAL DENSITY (skill-only). Two halves of one ask ("the UI must not use the AI em dash; less borders/cards, no cards inside cards"), routed by the three-tier doctrine. (1) The DASH is gateable, so it is a rule over UI-rendering files (`*.tsx/jsx/vue/svelte/astro/html/htm/ts/js/mts/cts`; markdown deliberately NOT scanned - prose files legitimately vendor and quote third-party text). Severity is BLOCK, not warn, because a warn exits 0 and is never fed back to the model - the whole complaint is that the model keeps writing them, so it has to reach the model. Precedent: `db-uuid-pk` is equally opinionated and blocks. PRECISION (measured over ~1100 real UI files in `references/repos` + packages + apps): the character must sit BETWEEN TEXT (`[A-Za-z0-9)\].,:%!?]\s*[dash]\s*[A-Za-z0-9(\["'\`]`) - that one requirement removed the ONLY real false-positive class, the STANDALONE GLYPH (`return "-"` for an empty table cell, `<span>-</span>`, a CLI bullet), which is a deliberate symbol and not copy (283 -> 225 hits, all remaining ones genuine prose dashes). The leading lookahead then drops DATA lines: a sanitizer (`.replace`/`normali`), a character/entity table (`mdash`/`ndash`/`fromCharCode`/an escaped `\u201x`), an `enigma:`-marked line, and a TRAILING comment (`(?<!:)//` so a URL does not silence the line; the engine only skips a line that STARTS as a comment, and a dash in a developer note is not UI text). Escape hatches: `enigma:` on the line, or `enigma:allow-dash` anywhere in the file (via `absent`) for verbatim quoted text. HTML entities (`&mdash;`) are deliberately NOT matched - to a line regex an entity table and an entity in copy are identical. The characters are written as backslash-u2014/backslash-u2013 regex escapes in guardrails.ts and built with `String.fromCharCode` in the tests, so neither file contains what it forbids (and the rule never self-flags). enigma's own 203 source files: 0 hits. GLOB LESSON (same class as the `**/*.prisma` gotcha above): `**/dist/**` does NOT match a ROOT-LEVEL `dist/main.js` - `**` maps to `.*` and the pattern still requires a leading `/` - so every generated/vendored tree is listed twice (`**/dist/**` AND `dist/**`). The older fe- rules still carry the one-sided form. (2) VISUAL DENSITY is NOT gateable and there is an explicit NOTE in guardrails.ts saying so: "card inside a card" and "border with no information" are RELATIONAL (a container is redundant only relative to its ancestor and the surrounding spacing; a border is legitimate on an input, a table edge, a flush row list), so any regex over `rounded-lg border` flags correct markup - it stays in frontend-policy's expanded "Visual Hierarchy & Layout Restraint" (one surface level; spacing -> background tone -> border, never two of the three on one boundary; one light source for shadows) with a short pointer in frontend-design's restraint section. Copy rule lives in technical-writing-policy ("never a typographic dash", with the dash-is-the-subject and verbatim-quote carve-outs).
- MEMORY KERNEL (the SEMANTIC half). Convention items with no reliable syntactic signature (optimistic UI, cache reads short-TTL/localStorage, real-time form validation, "validate every input with a schema discriminated by event") are NOT gateable by regex, so they live in the ALWAYS-ON deployed memory (`assets/memory/{CLAUDE,AGENTS}.md`) as a new `### Engineering Defaults (Always-On)` block (plain always-on text, NOT an enigma-marker toggle - it must always apply), generic + tool-per-language (Zod/TS, Pydantic/Py, ...). This is the tier-1 "restate the non-negotiable skill core in memory so it survives skill-skipping" pattern. So the guardrails feature now spans BOTH levers: guardrails = syntactic gate, memory kernel = semantic default. SCALABILITY RULE (user-mandated, supersedes the old "all semantic conventions -> memory" default): the always-on memory file is loaded EVERY session, so it does NOT scale - it is reserved for a MINIMAL set of TRULY UNIVERSAL, cross-cutting defaults that apply regardless of task domain (the input-validation / reusable-component / no-native-dialog / real-time-form-validation kernels already there). A convention scoped to ONE domain (a frontend display convention, a specific library recommendation, a UX pattern that only matters when doing UI work) lives ONLY in its DOMAIN SKILL, NOT the memory kernel - the skill is progressive-disclosure (loaded only when that domain is in scope = zero token cost otherwise), which is the scalable channel. So route by THREE tiers: (1) file-local regex signature, precise, low-FP -> a guardrail engine rule (token-free); (2) domain-scoped semantic, no signature -> the matching DOMAIN SKILL only (never duplicate its detail into memory); (3) truly universal semantic, no signature, must apply to every task -> the always-on memory kernel, kept minimal. NEVER put the same convention in both a skill AND the memory kernel (the duplication wastes always-on tokens and does not scale). Concretely: the real-time client-side uniqueness check and the `<relative-time>` date-display convention are domain-scoped (frontend) -> they live in frontend-policy/validation-policy ONLY; they were removed from the memory kernel after being briefly (mis)placed there.
- SEED RULES original detail: `db-uuid-pk` (BLOCK) matches ONLY explicit auto-increment identity signals `SERIAL|BIGSERIAL|AUTO_INCREMENT|IDENTITY(|GENERATED ... AS IDENTITY|@default(autoincrement())|@PrimaryGeneratedColumn()` - deliberately NOT plain `INTEGER PRIMARY KEY` (valid; enigma's own recall SQLite store uses it) nor `IDENTITY_INSERT`; precision over recall so a false positive never trains `--no-verify`/ignore. `db-ts-orm-prisma` (WARN, project) = TS project (`typescript` dep or tsconfig.json) + a relational/ORM dep (typeorm/sequelize/knex/drizzle-orm/pg/mysql2/better-sqlite3/@mikro-orm/core) + no prisma/@prisma/client. GLOB GOTCHA: `**/*.prisma` does NOT match a root-level `schema.prisma` (needs a slash); use BASENAME globs (`*.prisma`, `*.sql`, `*.entity.ts`, `package.json`, `schema.ts`) which match at any depth incl. root, plus dir globs (`**/migrations/**`) for nested non-standard extensions.

- CONTEXT BUDGET (`ctx-memory-budget`, BLOCK, 40 KB over `CLAUDE.md`/`AGENTS.md` basenames). The rule that keeps an always-on memory file from turning into a knowledge base - the failure that produced a 215 KB repo `CLAUDE.md` here, paid on every session regardless of the task. Size has NO regex form, so `GuardrailRule` gained `maxBytes?: number` (file scope) and `checkFile` branches on it BEFORE the pattern branch; the finding appends the measured size to the message so the number is visible without opening the file. BLOCK, not warn, for the same reason as `ui-no-em-dash`: a warn exits 0 and never reaches the model that keeps growing the file, and the fix (index + on-demand `docs/notes/<topic>.md`) is mechanical. The message teaches the three-tier routing (guardrail rule / domain skill / memory kernel) and names `enigma guardrails disable ctx-memory-budget` as the escape, since a project may legitimately keep a large hand-authored memory file. Only those two basenames are in scope: every other doc is read on demand and costs nothing until opened. The twin gate for enigma's OWN shipped kernel is `MEMORY_BUDGET_BYTES` (24 KB) in `checkSources` (skills.ts), which fails `enigma check`/`npm run verify` when `assets/memory/*.md` grows past it.
