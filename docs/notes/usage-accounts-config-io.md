- LIVE WINDOWS FROM RATE-LIMIT HEADERS (the real %, like Claude's UI). Anthropic returns the true usage windows in `/v1/messages` RESPONSE headers - `anthropic-ratelimit-unified-5h-utilization`/`-5h-reset` and `-7d-utilization`/`-7d-reset` (utilization is a 0..1 fraction; reset is epoch SECONDS) - plus optional `-7d-opus-*`/`-7d-sonnet-*`. This is how `claude-usage-tracker` does it (it fires a probe `/v1/messages`; enigma gets them FREE from real traffic because the proxy already sits on that path). `proxy.ts recordLimits(headers)` parses them in `forward`'s upstream-response callback and persists `ProxyLimits` to `~/.enigma/proxy/limits.json` (merging so a response missing a window keeps the last value); `readProxyLimits()` exported. `usage.ts computeWindows` OVERLAYS them onto the transcript-based windows: `pct = utilization*100` (capped; 0 if the reset already passed), `resetsAt` from the header, `live:true` - so the bars show the real % with NO plan limit set. Falls back to the transcript estimate / configured plan limit when no headers captured yet. REQUIRES the proxy on AND launching via `enigma claude` (else the proxy never runs). Per-model (Sonnet) live data only when Anthropic sends the `-7d-sonnet-*` headers, else transcript estimate. UI: dashboard window card shows a `live` tag; TUI winLine shows "(live)". Layering: usage.ts now imports proxy.ts (proxy->guard only, no cycle). Tests: `tests/proxy.test.ts` captures the headers e2e; `tests/usage.test.ts` overlays a written limits.json. WHY this beats the manual plan-limit: the user does not know their plan's token cap (Anthropic publishes none in tokens), so % needs either the API or these headers - we use the headers we already see.
- ACTIVE USAGE PROBE (`src/claude-usage-api.ts`, config `usageApi`, CLI `usage-api`, default OFF). The live-headers approach above only works when the proxy is ON and you launch via `enigma claude`; otherwise the windows show "window N% elapsed" (time, not usage) because `pct` is null. This module fills the gap so the REAL % shows with NO proxy: it reads the local Claude Code OAuth token (`<CLAUDE_CONFIG_DIR|~/.claude>/.credentials.json` -> `claudeAiOauth.accessToken`/`expiresAt`; managed accounts under `~/.enigma/claude/<name>/.credentials.json`, default preferred) and sends ONE minimal `/v1/messages` probe to api.anthropic.com (`Bearer` + `anthropic-beta: oauth-2025-04-20` + `anthropic-version: 2023-06-01` + `user-agent: claude-code/<ver>` (the UA is REQUIRED - without `claude-code/*` you hit an aggressively rate-limited 429 bucket) + body `{model: claude-haiku-4-5-..., max_tokens:1, "hi"}`), then feeds `res.headers` to the EXPORTED `recordLimits` (proxy.ts) which writes the same `limits.json` computeWindows already overlays - so ZERO new overlay wiring. WHY a probe not `GET /api/oauth/usage`: that dedicated endpoint is DISABLED for CLI OAuth tokens (confirmed in the `claude-usage-tracker-hamed` reference clone, which abandoned it for the same messages-probe); the rate-limit headers ride ANY `/v1/messages` response (even non-200), so we read them regardless of status. SAFETY/CONSENT: opt-in because it makes a network call with the user's token and consumes a hair of quota (one 1-token message); READ-ONLY on credentials (never writes/refreshes `.credentials.json` - refreshing rotates the token and could corrupt Claude's own auth; an expired token just means no probe until the next `claude` run refreshes it); the token goes ONLY to Anthropic, never logged/stored/written to any enigma file. THROTTLE: `maybeProbeUsage()` (fire-and-forget, called at the top of `buildUsage`) is gated by `usageApi && usageStats`, min 180s between attempts via a shared `~/.enigma/proxy/probe.json` stamp (stamped BEFORE the call so offline/expired-token machines are throttled too) + an in-process `probing` guard. Layering: claude-usage-api -> config + proxy (recordLimits); usage.ts -> claude-usage-api; NEVER the reverse. Surfaced in settings ("Live usage windows", Local dashboard category, globalOnly) + the dashboard "Enigma Systems" panel (`usageApi` in systemsStatus). Tests: `tests/claude-usage-api.test.ts` (token read/expiry + throttle gating, network-free - the probe HTTP path is not unit-tested, only the deterministic gating). Reference clone: `references/repos/claude-usage-tracker-hamed` (Swift, gitignored).
