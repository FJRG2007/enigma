# Text overflow: the flexbox rule almost everyone (including this repo) gets wrong

- SYMPTOM that started it: the committed dashboard screenshot showed the "Local API server (OpenAI-compatible)" card pushing its value tag and agent icons OUTSIDE the panel. Cause: `.sys-item` is a grid item and its `.k`/`.v` are flex items, all at the default `min-width: auto`, and `.v` was additionally `flex: 0 0 auto` - so a long label/value could not shrink and widened the row past its track. Fix: `min-width: 0` on the item and both halves, `flex-wrap: wrap` so the value drops to its own line, `overflow-wrap: anywhere` on the label, `flex: 0 1 auto` on the value.
- THE RULE, precisely (CSS Flexbox 4.5): a flex/grid item's automatic minimum size applies ONLY while its computed `overflow` is `visible`; any other value resolves it to 0. Consequence that cost a wrong guardrail rule here: Tailwind's `truncate` sets `overflow: hidden`, so `<div class="flex-1 truncate">` ALREADY shrinks and ellipsizes and does NOT need `min-w-0`. A `fe-flex-truncate-min-width` rule was written flagging exactly that, with three tests asserting the wrong behavior; the gate's reviewer caught it and a browser measurement confirmed it (`flex-1 truncate` fits; `flex-1` + nowrap with visible overflow does not; a flex item with visible overflow WRAPPING a truncating child does not). The rule was deleted - the real defect spans parent and child, so it has no single-line signature and stays in frontend-policy as guidance. `guardrails.ts` carries a NOTE where the rule was, so nobody re-adds it.
- WHAT IS GATEABLE, and the line it falls on: the LAYOUT half is not (it is a relation between an ancestor's overflow and a child's), the CLIPPING half is (the element that clips is the element that hides the value, so that one element answers "can the user still read this?"). Two rules: `fe-ellipsis-without-overflow` (text-overflow:ellipsis with no overflow value is inert - unambiguous) and `fe-truncated-value-unreachable` (a clipped dynamic value with no `title`/`aria-label`/tooltip on it or its wrapper). Everything else about variable-length text is semantic and lives in frontend-policy's "Text That Does Not Fit" section (domain-scoped = zero tokens unless doing frontend, per the 3-tier routing doctrine; it is NOT memory-kernel material).
- THE CLIPPING RULE AND ITS FIXER, and why this one is worth the volume. Report: "a card with a user's data deforms when the name is long, the buttons get squashed, the text drops half a line". The layout half of that was already all measured and rejected above; what had NEVER been gated is the OTHER consequence, which is that the value becomes unreadable with no way back. RE-MEASURED over 9079 UI files after the review anchored `DYNAMIC_CHILD` to a tag close: 3344 lines declare a clip and 1426 clip a dynamic value with the full string reachable nowhere - so this is what most real code does, which forces the DIFF stage (an edit-stage rule would report a project's existing rows forever) and makes the FIXER the point rather than a nicety: 1159 of the 1426 (81%) are repaired by code with no message, no turn and no tokens, and only the remaining 19% reach the model. The fixer copies the child expression into `title={...}` and declines everything it cannot copy safely - `{children}` and friends bare or dotted (not text, renders `[object Object]`), a fallback expression (`{host ?? "Not recorded"}` - copying `host` drops the fallback), a call, a capitalised component that may not forward the attribute, two elements on one line, and any non-JSX file. It builds its replacement out of the file's own source, so it passes a replacer FUNCTION to `String.prototype.replace` - a `$&`/`` $` ``/`$'`/`$$` in an attribute value is otherwise re-read as a substitution token and the "repair" corrupts the line. `line-clamp` is deliberately out of scope: a two-line clamp is body copy and a tooltip on a paragraph is not the convention.
- THE FALSE POSITIVE THE FIRST CUT SHIPPED, worth keeping because the shape recurs: `DYNAMIC_CHILD` was `/>\s*\{/`, which also matches the `> {` of an ARROW FUNCTION body - so `const truncate = (s, n) => { ... }` or a `useMemo(() => { ... truncate(x) ... })` was a BLOCK finding, the fixer correctly declined it, and the turn was denied over code that clips nothing with no exit but a marker on an unrelated line. Anchored with a lookbehind excluding every operator that ends in `>` (`=>`, `<=`, `>=`, `!=`, `-->`, `>>`). It removed no corpus finding, which is the lesson: a corpus scan measures VOLUME, not correctness - the shape was rare in product code and common in the code an agent writes, so only a probe found it. Any rule keyed on a bare `>` needs the same anchor.
- THE ENGINE CHANGE IT NEEDED, which is reusable: fixers ran ONLY in the post-edit hook, so a diff-stage rule could not have one. `applyFixes` now takes the stage (re-checking at the edit stage would drop every diff-stage finding from `remaining` and report a failed repair as a success), and `scanConventions` applies fixers before reporting - handing over ONLY the findings whose line the change ADDED. That restriction is the whole safety property: the sweep reads whole files, and repairing a pre-existing line would rewrite code the agent never wrote and put it in the user's diff. Pinned by a test that leaves a committed file breaking the same rule untouched while the new line is repaired.
- REJECTED WITH IT (measured over the same corpus, and the reason is always the same - whether a value is BOUNDED is not in the line): `whitespace-nowrap` on a dynamic value with no clipping (91 hits, majority correct - dates, amounts, durations, short type labels are what nowrap is for), a fixed-width box holding an unclipped value (207, same), and a translated string inside a hard box (10 candidates, about half `sr-only` spans or an input placeholder). The i18n question the report raised - "is this string translated? then its length is variable" - is a DESIGN-TIME check with no signature, so it went to frontend-policy as two questions to answer before laying anything out.
- VERIFY LAYOUT BY MEASURING, not by looking: `scripts/dashboard-preview.mjs` + Playwright (present in node_modules, CI-only as a dep) measuring `scrollWidth > clientWidth` and bounding rects against the container, across 1440/1024/768/390 AND with deliberately long text injected. Always confirm the check FAILS on the pre-fix CSS before trusting a pass - the first run here passed on both, which would have been a vacuous test. Regenerate the committed preview with `node scripts/screenshot.mjs` after a dashboard UI change.
