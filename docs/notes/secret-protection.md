# Secret protection: granular guard + prompt secret guard

- GRANULAR GUARD CONFIG. The guard's `~/.enigma-guard.json` (and per-repo `.githooks/enigma-guard.json`) gained THREE user lists ON TOP of the 6 boolean protections: `blockPaths` (extra globs to block), `allowPaths` (allowlist - skip ALL checks for matching files, evaluated FIRST so it wins over every rule), `secretPatterns` (extra secret regex sources). Schema/metadata/writer live in `src/guard-config.ts` (`GuardLists`, `GuardListMeta`, `GUARD_LISTS`, `setGuardList`; `readGlobalGuard` defends array fields; the writer now persists protections THEN lists so a protection toggle never drops the lists, and vice-versa). The self-contained `src/guard.ts` consumes them: `globToRegExp` (own glob->regex: `**` crosses `/`, `*` within a segment, no-slash glob matches basename), allowlist `continue`, blockPaths block, custom regexes folded into `scanSecrets`. guard.ts STILL imports nothing from enigma (keeps `dist/guard.js` standalone) but now EXPORTS the detection primitives (`SECRET_PATTERNS`, `buildSecretMatchers`, `findSecrets`, `redactSecrets`, `SecretMatcher`, `globToRegExp`) so other modules reuse ONE detection source.
- PROMPT SECRET GUARD (the "not only for git" part). Config `promptSecretGuard` (default OFF/opt-in) + `promptSecretMode` (`redact`|`reject`, default `redact`) in `config.ts`. When on, `accounts.ts launchTool` starts the proxy for Claude even if the measuring `proxy` flag is off (condition is `cfg.proxy || cfg.promptSecretGuard`) and passes scan options. `src/proxy.ts` `startMeasuringProxy(options)` gained `{scanPrompts, mode, extraPatterns}`: with `scanPrompts`, POST `/v1/messages` bodies are BUFFERED (the one place it is no longer a pure pass-through - default-off keeps it byte-faithful), scanned via guard.ts matchers (built-ins + `readGlobalGuard().secretPatterns`), then either redacted (placeholder, content-length rewritten, forwarded) or rejected (Anthropic-style 400, upstream never hit). New stats `redacted`/`rejected`/`lastBlockedAt` in `ProxyUsage` via `recordBlock`. The proxy `forward()` helper was factored out so both the streaming pass-through and the rewritten-body path share the upstream+measure logic. WHY the proxy (not a hook): the secret must be stopped BEFORE it leaves the machine to the model; the proxy is the only point that sees the outgoing request.
- LIST-SETTING UI (full visual editing in BOTH surfaces). `settings-registry.ts` `Setting` gained `kind:"list"` + `listValues`/`addItem`/`removeItem` + `itemHint` (cached/busted by `withReadCache` like the other accessors). `guardListSetting` builds one per `GUARD_LISTS` (globalOnly); the prompt-guard toggle + `prompt-secret-mode` choice live in a new "Prompt secret guard" category, the 3 lists are appended to "Commit guard". Bridged to the dashboard by `dashboard-settings.ts` (UiSetting `kind`/`items`/`itemHint`; `applySetting` handles `{op:"add"|"remove", item}`); the dashboard `index.html` renders chips + add-input (event delegation on `#settingsBody`, reloads on change). The TUI (`tui/opentui.ts`) adds a `listEdit` overlay (plain list view, single-letter keys: `a` add via the nested `listAdd` input overlay, `d`/delete remove, enter/esc done, mouse-click removes) - mirrors the identity-panel + add-input pattern; activating a `kind:"list"` row opens it instead of cycling. CLI: `enigma config <list-key> add|remove <entry>` (key alone lists) in `settings.ts`, before the boolean/choice path.
- TWO-VALUE CHOICE = SELECT, NOT SWITCH (gotcha). The dashboard/TUI render a choice as a SWITCH when `choices.length===2 && choices.indexOf(offChoice)!==-1`, else a SELECT. `enigmaChoice` ALWAYS sets `offChoice`, so a genuine two-action choice built with it (e.g. `prompt-secret-mode` = redact/reject, where neither value is "off") wrongly rendered as an on/off toggle. FIX: inline the `Setting` with `choices` but NO `offChoice` (so `offChoice` defaults to the sentinel "off", which is not in the list -> SELECT), exactly like `skill-update-policy`. `prompt-secret-mode` now does this; the boolean `read`/`write` face stays as a fallback (reject<->redact). When adding a 2-value choice that is NOT an on/off pair, do NOT use `enigmaChoice` - inline it without `offChoice`.
- DASHBOARD PORT (numeric, customizable from the dashboard). `dashboardPort` (config.ts, default 0=auto) is the dashboard's preferred bind port, a NUMERIC knob OUTSIDE the boolean/choice registry (same pattern as token-price/token-speed/plan limits): CLI `enigma config dashboard-port <0-65535>` (numeric branch in settings.ts), and a dedicated `POST /api/dashboard-port` route (writeDashboardPort, origin-guarded, validates 0..65535). `listenWithFallback` (dashboard.ts) tries the configured port FIRST when >0, then falls back to 80 -> 24282 -> ephemeral, so the dashboard always opens; the bound port is tracked in module `boundPort` and surfaced (with the configured `dashboardPort`) in the `/api/settings` GET payload. The dashboard `index.html` renders a static "Dashboard port" panel below `#settingsBody` (number input + Save -> `/api/dashboard-port`), populated by `renderDashPort(data)` from that payload; changing it needs a dashboard RESTART to rebind (the running server can't move ports live). Round-trips via config export/import (`dashboardPort` added to `NUMERIC_KEYS` in dashboard-config-io.ts). Test: `tests/dashboard.test.ts` covers the payload fields, prompt-secret-mode being a SELECT, the valid/invalid/cross-origin port writes. (dashboard 0.1.38.)
- INSTALL RECOMMENDATION. The git-hooks offer (`maybeOfferGitHooks`, security.ts) is now default-yes "(recommended)". `resolveSecretGuard` (skills.ts, after `resolveDashboard`) offers the prompt guard at install - default NO (the user required it off by default); honors `--prompt-secret-guard` (CLI flag + `InstallOptions.promptSecretGuard`). Status: `dashboard-status.ts` exposes `promptSecretGuard`/`promptSecretMode` + the block stats; the dashboard "Enigma Systems" panel renders state + measured redacted/rejected counts. Tests: `tests/guard.test.ts` (glob/matcher/redact + list persistence) and `tests/proxy.test.ts` (redact strips the key from the upstream body, reject 400s before upstream, clean body byte-identical). Test fixture credentials are built by string CONCATENATION at runtime so the repo's own commit guard does not flag the test files.
