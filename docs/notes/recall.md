# Recall: local session memory (`src/recall/` + `enigma recall`)

- WHAT: a de-branded, lean port of the CORE of `thedotmack/claude-mem` (study clone `references/repos/claude-mem`, Apache-2.0; the upstream is a ~36k-LOC plugin with a worker HTTP service, Chroma vectors, a web viewer and LLM-written observations). enigma ports only the durable core: transcripts -> structured observations + per-session summaries -> a local SQLite store -> search + retrieval, surfaced in the CLI/TUI/Dashboard and exposed to agents over MCP. DELIBERATELY UN-BRANDED per user instruction: nothing user-facing says "claude-mem"; the feature is "recall" (distinct from enigma's existing "agent memory" = the `CLAUDE.md`/`AGENTS.md` editor in `dashboard-memory.ts`, which is unrelated). Storage decision (user, after the zero-deps conflict was surfaced): `bun:sqlite`, NOT Prisma (Prisma's codegen + native engine break the single compiled-binary, zero-runtime-deps posture; bun:sqlite bundles into the binary and was verified working in the compiled `.exe`, FTS5 included). Compression decision: deterministic transcript extraction (no LLM call, free, offline, reproducible), NOT the upstream's Agent-SDK-written observations.
- MODULES (`src/recall/`): `types.ts` (RecallSource/ObservationType/Observation/SessionSummary/RecallStats), `db.ts` (lazy `require("bun:sqlite")` behind `RecallUnavailableError` so the Node/tsx dev path degrades; schema + FTS5 external-content `observations_fts` with insert/delete/update triggers; `recallDir()` honors `ENIGMA_RECALL_DIR`), `store.ts` (parameterized CRUD + `searchObservations` via `bm25`, `ftsMatch` sanitizes a query to safe prefix terms, dedupe via `UNIQUE(session_id, content_hash)` + `INSERT OR IGNORE`), `extract.ts` (turn-based deterministic extraction: a user prompt starts a turn, assistant text + Read/Edit/Write/NotebookEdit tool_use fill it; `inferType` keyword heuristic; `<private>` blocks dropped + secrets redacted via guard.ts `buildSecretMatchers`/`redactSecrets`; `isMeaningfulPrompt` rejects compaction markers + `toolu_`-id noise), `index.ts` (barrel: `syncRecall` incremental via `~/.enigma/recall/state.json` mtime/size cache, `searchRecall`, `recallContext`, `recallStatus`, `resetRecall`). IDENTIFIER DEVIATION from database-expert: INTEGER PKs not UUIDs - scoped + documented in db.ts (local single-user loopback file, no external ID exposure, FTS5 external-content needs an integer rowid, short ids are the citation UX `recall #42`).
- SHARED LEAF: `src/claude-transcripts.ts` (`claudeProjectsDirs`/`listJsonl`/`projectOf`) was EXTRACTED from usage.ts so usage AND recall share Claude-transcript discovery (reuse policy); usage.ts now imports it. Recall is Claude-only today; `source` is carried through every type/row so codex/opencode slot in behind the same store once their transcript format is verified (agnostic by construction; MCP injection already works for all three).
- CONFIG/SETTINGS: `recall` toggle (config.ts, default OFF/opt-in like `usageStats` - it reads your own transcripts; settings-registry "Local dashboard" category, globalOnly). No memory-marker (it does not alter deployed memory).
- SURFACES: CLI `enigma recall <status|sync|search|list|show|context|clear>` (`runRecallCli` in cli.ts, in COMMANDS + printHelp). MCP (`mcp.ts`): `enigma_recall` (compact search index) + `enigma_recall_get` (full by ids), listed by `toolList()` ONLY when `config.recall` is on AND `recallAvailable()`, and the call handlers refuse when off (never opens the DB) - this is how memory is injected AGNOSTICALLY (all three agents consume MCP). Dashboard: `src/dashboard-recall.ts` bridge (`recallDashboard` view + `applyRecallAction` sync/clear, with a throttled background sync so the panel stays fresh), `/api/recall` GET/POST origin-guarded in dashboard.ts, a "Recall" tab in `packages/dashboard/assets/index.html` (search box + type/project filters + brand-logo per source per the agent-logo convention); demo-mock stubs `/api/recall`; dashboard `0.1.57`. TUI: a "Recall memory" sideItem + read-only `renderRecallPanel` (mirrors the usage panel), so `tui.hub.test.ts`'s identity index is now `CATEGORIES.length + 6` (categories + usage + recall + resources + 3 actions).
- TESTS: `tests/recall.test.ts` (bun; temp HOME + `ENIGMA_CONFIG_HOME`/`ENIGMA_RECALL_DIR`/`ENIGMA_CLAUDE_PROJECTS` set BEFORE import; extraction, secret redaction, store dedupe/FTS, idempotent sync, MCP gating on/off - the on path uses `ENIGMA_CONFIG_HOME` to flip `recall` without touching the real config). Wired into ci.yml as its own step. NOTE the whole-suite `bun test` has pre-existing cross-test pollution on a machine with real `~/.enigma` state (gate/config-io fail in the shared process) - CI runs each file in its OWN process (one `bun test tests/X` step per file), which is the correct way to run them; every recall-touched file passes in isolation.
- DOCS: `apps/web/src/content/docs/concepts/recall.mdx` + a `reference/commands.mdx` entry + a `reference/configuration.mdx` row. To add another tool's transcripts: add a reader that yields the same `extractSession` output and a source dir to `claudeProjectsDirs` (or a sibling), tag the `source`; do NOT invent observations an LLM would write - keep extraction deterministic.
- PARITY EXPANSION (the "support everything claude-mem has" pass - feature parity translated to enigma's zero-deps architecture, NOT the literal Python/Chroma/Express): (1) HYBRID SEARCH - `src/recall/embed.ts` is a dependency-free embedder (signed feature hashing over word tokens + char trigrams, 256-dim L2-normalized, `EMBED_DIM`/`localEmbed`/`cosine`/`pack|unpackVector`, `EmbeddingProvider` seam for a real model later). A per-observation `observation_vectors(observation_id, vec BLOB)` table (FK cascade) is written inline by `insertObservation` (uses `res.lastInsertRowid`, verified to be the observation id not the FTS trigger's) + `backfillVectors`. `hybridSearch` (store.ts) fuses FTS bm25 + cosine via Reciprocal Rank Fusion; vectorSearch applies a MIN_COSINE=0.12 floor so feature-hash collisions don't leak into a filtered search. `searchRecall` is now hybrid. This is the Chroma role WITHOUT Chroma/Python (honest "semantic-lite": fuzzy lexical, real dense vectors need the provider hook). (2) 3-LAYER WORKFLOW - `timelineAround` (store) + `recallTimeline` + MCP `enigma_recall_timeline` + CLI `recall timeline <id>` + dashboard timeline view. (3) LLM OBSERVATIONS (opt-in) - `src/recall/enrich.ts` calls api.anthropic.com via the LOCAL Claude OAuth token (reuses `readOAuthToken` from claude-usage-api; UA `claude-code/*` required, model haiku, one batched call per session, parse strict JSON, best-effort/null on any failure). `enriched INTEGER` column (idempotent ALTER migration in openDb) is the resumable queue; `enrichRecall` (index.ts, throttled 60s, capped per pass) processes `sessionsNeedingEnrichment` -> `applyEnrichment` (overwrite fields + re-embed + mark) -> `markSessionEnriched` + upsert summary. Config `recallLlm` (default off; CLI key `recall-llm`; registry toggle). CLI `recall enrich`; `recall sync` also enriches when on. Claude-only, costs a little quota. (4) AUTO-CAPTURE (the worker's ingestion role, no HTTP daemon) - `syncForLaunch` fires a deferred background `syncRecall()`+`enrichRecall()` when `config.recall`, non-blocking. (5) RETENTION ("endless" role) - `prune({maxAgeDays,maxRows})` (count-diff, NOT `.changes` which triggers/cascade inflate) + `recall prune <n>`/`prune days <n>`. (6) WEB VIEWER - dashboard Recall rows expand to a detail (full narrative/facts/concepts/files) + a Timeline button (`/api/recall?timeline=<id>` -> `recallTimelineView`); `RecallItem` carries full fields so no refetch. Dashboard `0.1.58`. Tests in `tests/recall.test.ts` cover embeddings/hybrid/fuzzy/timeline/sessions/prune + LLM gating (network path is not unit-tested - opt-in, deterministic gating only). The literal Anthropic call in enrich.ts is verified only by gating tests (no egress in CI).
