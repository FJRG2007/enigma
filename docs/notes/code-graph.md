# Codebase memory / code graph (NATIVE) (`src/codegraph*.ts` + `enigma codegraph`)

- WHAT: a fully NATIVE, zero-dependency TS code-intelligence engine. Indexes a project's source into a knowledge graph - files, the symbols each defines (with a full line span + signature), the modules it imports, and symbol-to-symbol wiring - then answers both management queries (architecture/schema/search) and RETRIEVAL queries (ask/callers/skeleton/map/grep/check). STRUCTURAL code memory, complementary to `recall` (session memory). NO external binary, NO npx, NO third-party package. De-branding rule holds: no upstream project name anywhere. Study clones kept for reference only (gitignored): `references/repos/codebase-memory-mcp` (the original indexing idea), `references/repos/graft` (the retrieval layer + ranking model, MIT).
- FOUR MODULES (all Node-builtins only):
  - `codegraph-types.ts` - shared vocabulary: `EdgeRelation` (contains|imports|calls|references|extends|implements), `CodeEdge` = `[source, target, relation]` tuple, `WALK_RELATIONS` (everything but `contains` - a file contains every symbol in it, so walking it makes any file a false hub), `GraphNode`, `BodyIndex`. Exists ONLY to break the cycle between the builder and the rankers; do not add logic here.
  - `codegraph-extract.ts` - text -> facts. `symRules(lang)`/`importSpecs(lang)` per-language regexes (ts/js/python/go/rust/java/csharp/kotlin/ruby/php/c/cpp), `walk()` (IGNORE_DIRS; NOTE `bin`/`obj` deliberately NOT ignored - they collide with legit source dirs), MAX_FILES=8000 / MAX_FILE_BYTES=512KB, `scanFiles()` (shared with verify-parity.ts), `statSourceFiles()` (stat-only, for the drift probe), `importBindings()`.
  - `codegraph.ts` - resolution + storage. Mints node ids, resolves references into typed edges, persists `~/.enigma/codegraph/<sha1(root)[:12]>.json` + `.bodies.json` (`ENIGMA_CODEGRAPH_DIR` overrides), and keeps the original architecture/schema/search queries.
  - `codegraph-rank.ts` (tokenize/IDF/BM25/personalized PageRank/in-degree), `codegraph-query.ts` (ask/trace/skeleton/map/grep/check), `codegraph-format.ts` (rendering).
- THREE PRECISION FIXES that cost real debugging - do not regress them:
  1. **Symbol line is taken from the NAME's offset, not the match start.** A rule's leading `^\s*` swallows the preceding newline, so a match after a blank line begins ON that blank line. Symptom: empty `signature`, every span off by a line, grep attributing hits to the wrong symbol.
  2. **Spans are clamped to the next same-or-shallower-indent sibling** (`clampToSiblings`). Brace counting cannot see that `{` inside a regex literal (`[^;{)]`, `\{`) is not a block, and one such function otherwise swallows the whole rest of the file. Also: the body brace is the LAST `{` of the first line ENDING in one - not the first `{` seen - or a default parameter value (`opts: Options = {}`) closes the definition on its own declaration line.
  3. **A cross-file reference requires a real import BINDING, not just an imported module** (`binderFor`). Binding on a globally unique name made every local `out`/`dir`/`err` in the repo point at whichever single file declared that name: enigma's own map crowned `one` (a local arrow in `recall/store.ts`) as a 300-in-edge hub. `importBindings()` extracts the named/default/namespace bindings for ts/js/python; languages without them keep the looser module-level rule, which is the honest structural-lite floor. `ns.thing` resolves ONLY through a namespace import - any other `x.thing` is a property of a value.
  Related: hubs/hotspots/grep rank by **cross-file** in-degree (`inDegree(edges, true)`) - a hub is what OTHER files depend on.
- FRESHNESS: every file stores `size`/`mtimeMs`/`chars` at index time. `probeDrift()` = one stat per file, no reads. `loadFreshGraph(project, refresh=true)` re-indexes when the tree moved or the stored `version !== GRAPH_VERSION`, which is what makes every query describe the code as it is NOW (uncommitted edits included). `codeGraphCheck()` REPORTS drift and never repairs it (the CLI exits 1 when stale, so it gates CI); the dashboard panel shows it with a Re-index button for the same reason - a panel that re-indexed on render would re-parse the tree on every page load.
- PROJECT RESOLUTION: with nothing named, the project CONTAINING the cwd wins over the most recently indexed one (answering a question asked in repo B with repo A's graph is worse than saying nothing). `ensureProjectForCwd()` indexes the cwd when nothing covers it - the CLI and the MCP tools both call it, so an agent never has to run a setup command first.
- RANKING (`ask`): query terms are BINARY (a word repeated in a pasted issue counts once). Score = name overlap x3 + path overlap x2 + BM25 over the body bag, times a 0.35 test-file penalty (waived when the query itself asks about tests). Then personalized PageRank over WALK_RELATIONS, seeded by the lexical scores, blended at GRAPH_WEIGHT=0.5; a node the query never word-matched is rescued at RESCUE_FLOOR=0.15 of the top mass. A wiring-shaped query ("who calls X") skips all of that and answers from edges, and when it cannot it says so out loud before falling back to word matches. Body vocabulary comes from the `.bodies.json` sidecar (top 80 tokens per node) so `ask` never re-reads the tree.
- CONFIG: `codeGraph` toggle (config.ts, default OFF/opt-in). Wired as a custom `setCodeGraph` in settings-registry.ts -> `setEnigmaToggle` + `applyMcpToggle` (the tools ride the EXISTING `enigma` MCP server, NOT a second server).
- MCP (native, via `enigma mcp`): `mcpEnabled()` = `compress || recall || codeGraph`. `CODEGRAPH_TOOLS` appended to `toolList()` only when `config.codeGraph`: `_index`/`_projects`/`_search`/`_architecture` plus the retrieval four - `_ask`/`_trace`/`_skeleton`/`_map`/`_grep`, all routed through one `codeGraphRetrieval()` helper that returns the RENDERED report (an agent reads it better than JSON and it costs fewer tokens). Do NOT deploy a separate managed server.
- DASHBOARD: bridge `dashboard-codegraph.ts` (`codeGraphDashboard({project, ask})` + `applyCodeGraphAction` toggle|index|ask|refresh); origin-guarded `GET/POST /api/codegraph` in dashboard.ts (POST body carries `on`/`project`/`root`/`query`, query capped at 500 chars). The "Code graph" tab has a REAL switch (`class="toggle" data-kind="bool"` - the sliding-knob switch, NOT a text on/off button; repeat complaint), an "Index a project" input, an "Ask the graph" box (Enter submits), a Freshness panel with a Re-index button, the projects list and the `cgSection`/`cgVal` architecture/schema renderer.
- CLI: `enigma codegraph <status|on|off|index|projects|arch|search|ask|callers|callees|skeleton|map|grep|check>`. The retrieval subcommands own their own flags, so parseArgs FORWARDS everything after a codegraph subcommand verbatim (`--limit`, `--depth`, `--in`, `--source`, `-i`, `--fixed`, `--max-hits`, `--max-dirs`, `--json`, `--no-refresh`) instead of matching it against the shared option table - otherwise the global parser rejects flags it was never meant to own.
- TESTS: `tests/codegraph.test.ts` (extraction, edges, spans, the regex-brace case, the import-binding precision rule, drift) and `tests/codegraph-query.test.ts` (ask ranking + structural intent + `--in`, trace in/out/depth, skeleton, map hubs, grep grouping and truncation, check, and that a query refreshes first). Both pin `ENIGMA_CODEGRAPH_DIR` + `ENIGMA_CONFIG_HOME` BEFORE import. Wired into ci.yml.
