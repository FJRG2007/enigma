# Codebase memory / code graph (NATIVE) (`src/codegraph*.ts` + `enigma codegraph`)

- WHAT: a fully NATIVE, zero-dependency TS code-intelligence engine. Indexes a project's source into a knowledge graph - files, the symbols each defines (with a full line span + signature), the modules it imports, and symbol-to-symbol wiring - then answers both management queries (architecture/schema/search) and RETRIEVAL queries (ask/callers/skeleton/map/grep/check). STRUCTURAL code memory, complementary to `recall` (session memory). NO external binary, NO npx, NO third-party package. De-branding rule holds: no upstream project name anywhere. Study clones kept for reference only (gitignored): `references/repos/codebase-memory-mcp` (the original indexing idea), `references/repos/graft` (the retrieval layer + ranking model, MIT).
- FOUR MODULES (all Node-builtins only):
  - `codegraph-types.ts` - shared vocabulary: `EdgeRelation` (contains|imports|calls|references|extends|implements), `CodeEdge` = `[source, target, relation]` tuple, `WALK_RELATIONS` (everything but `contains` - a file contains every symbol in it, so walking it makes any file a false hub), `GraphNode`, `BodyIndex`. Exists ONLY to break the cycle between the builder and the rankers; do not add logic here.
  - `codegraph-extract.ts` - text -> facts. `symRules(lang)`/`importSpecs(lang)` per-language regexes (ts/js/python/go/rust/java/csharp/kotlin/ruby/php/c/cpp), `walk()` (IGNORE_DIRS; NOTE `bin`/`obj` deliberately NOT ignored - they collide with legit source dirs), MAX_FILES=8000 / MAX_FILE_BYTES=512KB, `scanFiles()` (shared with verify-parity.ts), `statSourceFiles()` (stat-only, for the drift probe), `importBindings()`.
  - `codegraph.ts` - resolution + storage. Mints node ids, resolves references into typed edges, persists `~/.enigma/codegraph/<sha1(root)[:12]>.json` + `.bodies.json` (`ENIGMA_CODEGRAPH_DIR` overrides), and keeps the original architecture/schema/search queries.
  - `codegraph-rank.ts` (tokenize/IDF/BM25/personalized PageRank/in-degree), `codegraph-query.ts` (ask/trace/skeleton/map/grep/check), `codegraph-format.ts` (rendering).
- THE SCAN ASKS GIT FIRST (`gitSourceFiles`), and only walks the tree when there is no repo or no git. `git ls-files --cached --others --exclude-standard -z` is the exact question: the files this project owns, ignored ones excluded. Found on a real project - 250 source files beside a 228k-file download cache - where the walk cost 18 s. That is not an indexing cost: `statSourceFiles` walks too, so EVERY drift probe (i.e. every query and every hook) paid it. Now ~0.1 s. The fallback walk is bounded twice over: breadth-first (the budget is spent on the shallow directories source lives in, not on the first deep tree it descends into) and capped at MAX_ENTRIES=60000 VISITED entries - the old MAX_FILES cap counted only source files ACCEPTED, which a tree of non-source data never reaches, so it protected nothing. Both caps set `truncated`. A SUBMODULE is one gitlink entry in that listing, never its contents, so a superproject's submodule source vanished from the graph without tripping anything: the outer repo still lists plenty of files, so the empty-answer fallback never fires and `truncated` stays false - complete coverage reported for a tree never seen. Fixed with a second pass, `git ls-files --recurse-submodules` (git only accepts it in `--cached` mode, so it cannot be folded into the first), run only when a `.gitmodules` exists and merged deduped.
- IMPORTS RESOLVE IN EVERY SPELLING, not just `./x` (`createImportResolver`). A relative specifier is a JS habit: Python writes `src.utils.basics` and `.sibling`, Go the go.mod module path, Java/C# a dotted namespace, PHP a backslashed one, Rust `crate::a::b`, an aliased TS import `@/lib/x`. Resolving only the dotted-path form gave a 125-file Python project **0 import edges** - no PageRank signal, no cross-file blast radius, and its own modules listed as third-party dependencies in the architecture view. Every candidate is verified against the real file set (`verifyModule`, incl. `index`/`__init__`/`mod` entry points), so a spelling that matches nothing resolves to nothing and a guess can never become an edge. A Go import binds the DIRECTORY, so the resolver returns a list. Measured on that project: 0 -> 212 import edges, references 309 -> 637, calls 637 -> 977 (the binder gets real import context too).
- A STORED GRAPH FROM AN OLDER SHAPE IS RE-INDEXED, NEVER RENDERED (`loadCompatibleGraph`). `loadFreshGraph` always handled the version, but `codeGraphArchitecture`/`codeGraphSchema`/`searchGraph` read raw `loadGraph` - so the dashboard happily rendered a pre-versioning graph and reported `IMPORTS 0` for a codebase full of them. Version mismatch re-indexes; DRIFT deliberately does not (stale format is unusable, stale content still answers, and re-parsing on every panel render turns a page refresh into a full index).
- FOUR PRECISION FIXES that cost real debugging - do not regress them:
  1. **Symbol line is taken from the NAME's offset, not the match start.** A rule's leading `^\s*` swallows the preceding newline, so a match after a blank line begins ON that blank line. Symptom: empty `signature`, every span off by a line, grep attributing hits to the wrong symbol.
  2. **Spans are clamped to the next same-or-shallower-indent sibling** (`clampToSiblings`). Brace counting cannot see that `{` inside a regex literal (`[^;{)]`, `\{`) is not a block, and one such function otherwise swallows the whole rest of the file. Also: the body brace is the LAST `{` of the first line ENDING in one - not the first `{` seen - or a default parameter value (`opts: Options = {}`) closes the definition on its own declaration line.
  3. **A cross-file reference requires a real import BINDING, not just an imported module** (`binderFor`). Binding on a globally unique name made every local `out`/`dir`/`err` in the repo point at whichever single file declared that name: enigma's own map crowned `one` (a local arrow in `recall/store.ts`) as a 300-in-edge hub. `importBindings()` extracts the named/default/namespace bindings for ts/js/python; languages without them keep the looser module-level rule, which is the honest structural-lite floor. `ns.thing` resolves ONLY through a namespace import - any other `x.thing` is a property of a value.
  4. **`#` is a line comment only where it IS one** (`braceEnd(lines, startIdx, lang)`, `HASH_COMMENT_LANGS` = php, plus a `#`-leading preprocessor line in c/cpp). Treating it as a comment for every brace language broke TS/JS private fields: `if (this.#store.has(key)) {` stopped the scan at the `#`, so the trailing `{` never incremented depth and the definition closed one block early - and sibling clamping cannot catch an UNDER-run, only an over-run. Rust `#[derive]` was the same class of bug one attribute at a time.
  Related: hubs/hotspots/grep rank by **cross-file** in-degree (`inDegree(edges, true)`) - a hub is what OTHER files depend on.
- HOOK BUDGETS ARE A HARD RULE: the three hooks on a 10 s budget (prompt, post-edit, stop) must NEVER index inline - they call `findProjectForCwd` (resolve, no side effect) and hand a missing index to a detached `codegraph index` via `backgroundIndex`, staying silent until it lands. `session-start` is the only one that may index inline (once, 20 s). Found in production: a cold index of this monorepo was 16 s with the unscoped scan against a 10 s budget, and the host DISCARDS the output of a hook that overruns - so the user paid a stall on every prompt and got nothing, with `UserPromptSubmit hook timed out after 10s` as the only clue. `backgroundIndex` is guarded twice over: it skips `isManagedPath` roots (there `indexProject` refuses by design, so the spawn is a process guaranteed to fail once per prompt and once per edit for the whole session) and claims a `<store>/sessions/indexing-<key>` marker with an `INDEX_COOLDOWN_MS=60000` window - without it a tree nothing covers gets a fresh full scan per prompt, each ending in a read-modify-write of `projects.json` that can drop what the others wrote. Skipping a refresh costs nothing: `loadFreshGraph` re-indexes on drift before it answers.
- `~/.enigma/**` IS NEVER A PROJECT (`isManagedPath`, enforced in `indexProject` and in the `listProjects` prune). The gate runs in a throwaway worktree under it, so with the graph on by default every run registered that checkout as a project named after its run ULID, duplicating a repo the user already had indexed and leaving ~25 MB per run behind. `indexProject` throws a named error rather than returning quietly - the CLI/MCP surface it, the hooks swallow it. That prune is the ONLY one that deletes: an entry whose root merely is not there right now is HIDDEN from `listProjects` and left on disk, because `existsSync` reads the same for an unmounted drive, a disconnected share and a permission change as for a deleted tree - and this is a read path every query runs, so deleting there made opening the dashboard with a volume detached cost a full cold re-index. `indexProject` merges into `storedProjects()` (the unfiltered list) for the same reason.
- ARCHITECTURE RANKING (the dashboard's panel): hotspots use CROSS-FILE in-degree (`topByCrossFileDegree`), the same rule `map` already used for hubs - counting every reference let a file's own locals win, so the panel read `path use match out field` instead of the shared plumbing. Entry points rank by how much of the project each pulls in (out-edge count, name-pattern as the tiebreak); before they were the first fifteen unimported files in SCAN ORDER, which listed shipped asset scripts ahead of `src/cli.ts`. `refs` (the per-name counter that ranking used to read) is GONE from the stored shape - nothing read it any more, and it was serialized into every graph file and counted in the index hot loop; `GRAPH_VERSION` 3 -> 4 carries the change, and `loadCompatibleGraph`/`loadFreshGraph` re-index a graph written by the older build.
- A REFERENCE CANNOT CROSS A LANGUAGE FAMILY (`LANG_FAMILY`/`langFamily`, applied in `binderFor`). A family is not one language KEY: `.h` keys as `c` while `.cpp`/`.hpp` key as `cpp`, so the first version of this rule dropped every edge from a C++ definition to the header declaring it - in practice all of them, in every C++ project. Families are ts+js, c+cpp and java+kotlin (same classes, direct interop); everything else stands alone. Name-based resolution had no such rule, and the loose fallback for languages without import bindings made the violation routine: 9761 of 21232 cross-file edges on this repo - 46% - pointed from one language at another, so a vendored Ruby SDK under `assets/` owned the hub list of a TypeScript monorepo (`value` in cli.ts with 1342 in-edges, `one` in recall/store.ts with 357). After: `packages/` hubs read `readConfig` 102, `readJson` 86, `isDir` 50. Vendored material that IS tracked still shows up in its own directory's hubs, which is honest - it is in the repo; no path heuristic de-ranks it.
- HONESTY OF THE ANSWER - three rules the retrieval layer must keep, because every one of them was a surface reporting success for something it did not do:
  - **A capped scan is carried, never dropped.** `scanFiles()` reports `truncated`; `indexProject` stores it on the graph AND the `ProjectEntry`, and `index`/`projects`/`check`/`map`/`grep` all say it. `grep` calls itself exhaustive, so a graph that never saw part of the tree has to say so - a no-hit result is exactly when it misleads most.
  - **A malformed flag or pattern is a usage error.** `parseQueryFlags` exits 2 on a missing value, a non-positive number, a bad `--direction` and an unknown `-`-prefixed token (same contract as the shared parser); `--` ends flag parsing, which is how a dash-leading grep pattern still gets through. An invalid regex throws `invalid regex: ...` rather than being silently re-read as a literal - that would answer a different search. (`searchGraph` still falls back to the escaped literal; it is a name filter, not a search the user typed as a regex.)
  - **Savings are measured against what the answer actually replaced.** `map`'s baseline is the files its hubs and hotspots point at, not every file in the repo - nobody reads a codebase whole to orient in it, so claiming that as the alternative is not a saving.
- FRESHNESS: every file stores `size`/`mtimeMs`/`chars` at index time. `probeDrift()` = one stat per file, no reads. `loadFreshGraph(project, refresh=true)` re-indexes when the tree moved or the stored `version !== GRAPH_VERSION`, which is what makes every query describe the code as it is NOW (uncommitted edits included). `codeGraphCheck()` REPORTS drift and never repairs it (the CLI exits 1 when stale, so it gates CI); the dashboard panel shows it with a Re-index button for the same reason - a panel that re-indexed on render would re-parse the tree on every page load.
- PROJECT RESOLUTION: with nothing named, the project CONTAINING the cwd wins over the most recently indexed one (answering a question asked in repo B with repo A's graph is worse than saying nothing). `ensureProjectForCwd()` indexes the cwd when nothing covers it - the CLI and the MCP tools both call it, so an agent never has to run a setup command first.
- RANKING (`ask`): query terms are BINARY (a word repeated in a pasted issue counts once). Score = name overlap x3 + path overlap x2 + BM25 over the body bag, times a 0.35 test-file penalty (waived when the query itself asks about tests). Then personalized PageRank over WALK_RELATIONS, seeded by the lexical scores, blended at GRAPH_WEIGHT=0.5; a node the query never word-matched is rescued at RESCUE_FLOOR=0.15 of the top mass. A wiring-shaped query ("who calls X") skips all of that and answers from edges, and when it cannot it says so out loud before falling back to word matches. Body vocabulary comes from the `.bodies.json` sidecar (top 80 tokens per node) so `ask` never re-reads the tree.
- DISCOVERABILITY - the tools being registered is NOT enough: an agent never told they exist keeps grepping, and the whole feature goes unused. The instruction lives in `core-engineering-policy`'s `enigma:config` block (case `codeGraph=true`), NOT in the always-on memory kernel - the kernel is at ~24000/24000 bytes and a block there fails `enigma check`. That also matches how the upstream reference does it (a skill file, never the user's CLAUDE.md). The setting carries `affectsSkills: true` so toggling re-renders the deployed skill. Pinned by `tests/skill-config.test.ts`.
- PUSH HALF - the session hooks (`src/codegraph-hook.ts` runtime + `src/codegraph-deploy.ts` wiring, Claude Code only; the other hosts have no per-prompt event, so wiring them would spend a process per turn for nothing). Four events behind `enigma __codegraph-hook <session-start|prompt|post-edit|stop>`, dispatched EARLY in cli.ts with a SYNCHRONOUS `readFileSync(0)` before any await - the guardrails-hook lesson: an await lets Node drain the pipe and the hook silently sees an empty payload. Output contract is `{"hookSpecificOutput":{"hookEventName":X,"additionalContext":Y}}` on stdout. Every path fails soft and exits 0: a hook must never break the turn it rides in.
  - `session-start`: repo map + a directive naming the tools. Paid ONCE and carried by the prompt cache, which is why it can afford to be the big one.
  - `prompt`: up to 3 LOCATORS, never `--source`. Per-prompt injection is full-price input on EVERY turn (unlike the cached session block), so inlining there would spend thousands of tokens a turn to save a read that may never happen. Three gates keep it quiet: `MIN_PROMPT_CHARS=12`, the two coverage floors, and per-session dedup of already-injected pointers. A repeated prompt does NOT go silent - it hands over the next-ranked hits, on the theory that the first pack did not help.
  - COVERAGE FLOORS (`STRONG_FLOOR=0.25` on `coverageStrong`, `BROAD_FLOOR=0.40` on `coverage`, pass on EITHER). `coverageStrong` was added to `AskResult` for this: measured on this repo, a real question can score 0.32 broad and resolve perfectly ("where is drift between the graph and the working tree detected") while another scores 0.54 broad on a 0.21 name match - one floor fails one shape or the other. Chatter topped out at 0.19 on BOTH. Six probes, one repo: a starting point, not a result.
  - `post-edit`: blast radius of the written file, `refresh: false` (the edit is milliseconds old; re-indexing per write makes editing progressively slower). `stop` does the one re-index per turn, detached, only when this session actually edited something.
  - STATUSLINE: `bin/statusline.mjs` is Node and the engine is Bun-compiled, so it can never call it - the same split that forces the gate snapshot. The hooks leave `<store>/statusline.json` (`{root,symbols,stale}`) and `readCodeGraphStatus` reads it, gated on `isInside(cwd, snap.root)` so another repo's numbers never land on this session's line.
- PROJECT RESOLUTION, TWO TRAPS BOTH FOUND BY TESTS: (1) `ensureProjectForCwd(dir?)` takes the directory - the hooks know which project they are speaking about and taking `process.cwd()` there answered about the wrong repo. (2) `projectRootOf` climbs ONLY on `.git`. Climbing on any marker let a temp dir borrow an unrelated ancestor's `package.json`, indexing 40k symbols of someone else's code to answer about four files; the walk is also bounded (`MAX_ROOT_WALK`) and never passes the home directory.
- CONFIG: `codeGraph` toggle (config.ts, default ON). `setCodeGraph` applies BOTH halves (`applyMcpToggle` + `applyCodeGraphWiring`), so enabling never leaves it half-wired - available but never arriving. Turning the default on changed 5 existing tests, all legitimately: the shared MCP server is now registered whenever ANY family is on, so the compress-only tests isolate themselves with `codeGraph:false` and one new test pins the shared-server truth. Wired as a custom `setCodeGraph` in settings-registry.ts -> `setEnigmaToggle` + `applyMcpToggle` (the tools ride the EXISTING `enigma` MCP server, NOT a second server).
- MCP (native, via `enigma mcp`): `mcpEnabled()` = `compress || recall || codeGraph`. `CODEGRAPH_TOOLS` appended to `toolList()` only when `config.codeGraph`: `_index`/`_projects`/`_search`/`_architecture` plus the retrieval five - `_ask`/`_trace`/`_skeleton`/`_map`/`_grep` (`check` stays CLI/CI-only, not exposed over MCP), all routed through one `codeGraphRetrieval()` helper that returns the RENDERED report (an agent reads it better than JSON and it costs fewer tokens). Do NOT deploy a separate managed server.
- DASHBOARD: bridge `dashboard-codegraph.ts` (`codeGraphDashboard({project, ask})` + `applyCodeGraphAction` toggle|index|ask|graph|refresh; `graph` returns the slice and NO view, so panning never rebuilds the architecture panel); origin-guarded `GET/POST /api/codegraph` in dashboard.ts (POST body carries `on`/`project`/`root`/`query`, query capped at 500 chars). The toggle goes through `applySetting("code-graph")` (dashboard-settings.ts), NOT `setEnigmaValue`: writing the value directly left the dashboard switch doing a third of what the same switch does from the CLI - config value written, MCP registered, but no session hooks and no skill re-render. It returns `{ok, enabled, note}` and NO view: nothing the panel renders depends on the toggle, and rebuilding it would stat the whole tree to re-answer a freshness question the toggle did not change. The switch is OPTIMISTIC with rollback (`paintSwitch`), like every other control here - the write behind it re-renders skills for every installed agent (~1 s), which is long enough that a switch waiting on it reads as dead. Recall's switch had the same defect and was fixed with it. The "Code graph" tab has a REAL switch (`class="toggle" data-kind="bool"` - the sliding-knob switch, NOT a text on/off button; repeat complaint), an "Index a project" input, an "Ask the graph" box (Enter submits), a Freshness panel with a Re-index button, the projects list and the `cgSection`/`cgVal` architecture/schema renderer.
- THE DRAWABLE SLICE (`codegraph-subgraph.ts`, `codegraph graph [focus]`, dashboard canvas). The stored graph is far too big to draw whole (23k symbols / 46k edges on this repo), so a slice is always SEEDED and CAPPED: no focus seeds the ranked hubs (`scope: "symbols"`) or the import graph (`scope: "files"`, built from `importEdges` - a file node's id IS its path, so an import edge is already a pair of node ids); a focus seeds `resolveSymbolNodes` and walks BOTH directions, which is the picture `trace` gives one direction of at a time. Eight rules that are not obvious:
  1. **An exact node id short-circuits name resolution.** A viewer expanding a node holds the id; re-resolving it by name re-runs the ambiguity the id exists to settle and re-centres on a same-named symbol in another file.
  2. **Edges are INDUCED, not the ones the walk traversed.** Carrying only traversed edges draws a tree of a graph and hides exactly the cross-links the picture exists to show. Neighbours left outside the slice are COUNTED per node (`hidden`), never dropped silently - that count is what the "+" badge and the Expand button are made of.
  3. **An unfocused symbol overview walks ONE hop regardless of `--depth`**: it is already the ranked answer, and walking it out drowns the hubs in the callers that made them hubs.
  4. **A focus that resolves to nothing returns an EMPTY result carrying the reason**, never the overview - drawing the overview instead answers a question nobody asked.
  5. **`hidden` counts only what EXPANDING could reveal, which is not "every edge that touches the node".** `contains` is not a walk relation, so the file->symbol direction counts (expanding a file re-seeds its symbols) and the symbol->file direction does not. Counting both put `hidden >= 1` on every node of every symbol slice - each one claiming its own file - so the canvas badged and offered Expand on everything and expanding added nothing. `neighbours` rides beside it as the WHOLE-graph total: a viewer merging slices needs it to recount `hidden` against the merged picture, because a slice-local count goes stale the moment a second slice is drawn beside it (`neighbours == drawn incident + hidden`, pinned by a test).
  6. **The cap binds the SEEDS, not just the walk.** A file seed carries every symbol that file defines, so a `--limit 10` used to answer with hundreds and still report `truncated: false`. Seeds are ranked, deduped, `--in`-filtered and capped like the walk's frontier, and a seed the ranking dropped raises `truncated` - the walk raising it alone misses the case where the walk finds nothing new to add (mutually-connected hubs, a repo of edgeless files).
  7. **`scope` decides the edge pool whether or not there is a focus.** Drawing the symbol graph while the result says `scope: "files"` labels the picture as something it is not, and made the dashboard's Scope dropdown a no-op the moment the focus box was filled. A focused file slice centres on the file the focus LIVES IN (a symbol seeded into the import pool sits there unreachable) and reports that file as the focus.
  8. **The slice's share is read against the population its own scope draws from** - `totals.importEdges` for a file slice, `totals.edges` for a symbol one. Measuring import edges against the symbol graph's total reported a complete file view as a fraction of itself. Same arithmetic in `formatSubgraph` and the dashboard's `cgRenderMeta`; they have to agree.
  `subgraphToDot` renders the same slice as Graphviz (escapes backslashes BEFORE quotes, or an escaped quote becomes an escaped backslash). `formatSubgraph` is the terminal version; both state the node cap AND the index cap, and a real-but-tiny share reads `<1%` rather than rounding to `0%`.
- DASHBOARD CANVAS (index.html, `cg*` functions). Hand-rolled force layout on ONE canvas - no graph library, no CDN: the dashboard ships as a single offline file. Seven things cost real debugging:
  1. **`.cg-overlay[hidden]` must be declared.** `display: flex` outranks the UA's `[hidden]` rule, so the dismissed "Drawing..." overlay kept covering the canvas and swallowed every click, drag and wheel event on it - the panel looked completely inert.
  2. **Separation is applied to the POSITION, not the velocity.** Charge alone loses to a node's own springs once it has a dozen neighbours; the result was the hairball where every hub sits underneath its callers. The separation pass runs inside the same 3x3 grid scan as repulsion, and runs regardless of how cold the layout is - it is the only thing that guarantees drawn circles do not overlap.
  3. **Repulsion is over a uniform grid, never all pairs**: at the 2000-node cap all-pairs is 4M distance checks a tick. Measured: 61 fps and a 1.5 s settle at 300 nodes / 960 edges.
  4. **Radius is in WORLD units and labels in SCREEN units.** A radius measured in screen pixels is a size the simulation cannot see, so at any zoom below 1 the dots grow past the spacing the layout worked out for them. Labels are drawn in a SECOND pass over all nodes, or a node drawn later covers the caption of one drawn earlier.
  5. **Colour says WHERE, shape says WHAT.** Colouring by kind made the file view (where every node is a file) one grey cloud. Groups come from the first path segment that actually SEPARATES the slice's paths (they usually share a long prefix), so the grouping stays meaningful at any `--in`.
  6. **The overlay belongs only to a draw that has nothing to show.** It is `inset: 0` over the whole `.cg-wrap`, so raising it after a failed EXPAND veils a perfectly good graph and swallows every click on it until the next Draw - the same inertness rule 1 was about. An expand that errors, returns nothing, or adds nothing reports as a toast and leaves the canvas alone.
  7. **A merge widens the picture; it does not re-answer what the picture is OF.** Taking the expand slice's meta relabelled the whole canvas with the expanded node's focus and reported its cap; the merged meta keeps the original focus and ORs the truncation flags. Node counts likewise: `cgRecount` derives every `hidden` from `neighbours` minus what the merged canvas actually draws, mirroring the engine's `contains` asymmetry (source always counts, target only when the relation is not `contains`).
  The label floor is set by node COUNT as well as zoom - a fifteen-node slice hiding its own names is the failure the zoom-only rule produces. The panel requests `limit: 200`, deliberately under the engine's cap. `demo-mock.js` answers `op: "graph"` with a fixed slice, or the public web demo's graph tab draws nothing.
- CLI: `enigma codegraph <status|index|projects|arch|search|ask|callers|callees|skeleton|map|grep|graph|check>`. `check [project]` takes the project as a POSITIONAL as well as `--project`: it reads as naming one, and taking the cwd anyway answered about a different repository, silently. An explicit `--project` still outranks the positional, as it does in every other subcommand. There is deliberately NO `codegraph on|off`: it was the ONLY subcommand in the CLI with a bespoke on/off alias (recall and compress have none), and it hardcoded the global scope, so `codegraph on -l` silently wrote the global config. It now prints the canonical `enigma config code-graph on [-l]` and exits 2 - one way to change a setting. The retrieval subcommands own their own flags, so parseArgs FORWARDS everything after a codegraph subcommand verbatim (`--limit`, `--depth`, `--in`, `--source`, `-i`, `--fixed`, `--max-hits`, `--max-dirs`, `--json`, `--no-refresh`, and `--`) instead of matching it against the shared option table - otherwise the global parser rejects flags it was never meant to own. That forward is checked BEFORE the `--` passthrough branch on purpose: codegraph forwards nothing to another tool, so `--` belongs to `parseQueryFlags` as its end-of-flags marker.
