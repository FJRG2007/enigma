# System resources / process killer (`src/resources.ts` + `enigma resources` / `enigma kill`)

- DESTRUCTIVE system cleanup across all three surfaces (CLI/dashboard/TUI), built for the Windows pain points: WSL's `vmmemWSL` lightweight VM (freed with `wsl --shutdown`) and Docker Desktop not actually quitting. `src/resources.ts` (Node-builtins only) is the engine: PURE exported PARSERS (`parseTasklist`/`parsePs`/`parseNetstat`/`parseLsof`) - the only unit-testable part, tested WITHOUT spawning/killing (`tests/resources.test.ts`); queries (`listProcesses` top-by-mem, `listPorts` LISTENING TCP + owning process name, `resourceStatus`); destructive actions `killPid` (taskkill /F | SIGKILL), `freePort` (kill every listener on a port), `shutdownWsl` (`wsl --shutdown`), `quitDocker` (force-kill "Docker Desktop.exe"+com.docker.* THEN shutdownWsl - Docker first, then WSL, the safe order). `runResourceAction(op, value)` dispatches by name. Windows-first; POSIX has ps/lsof process+port support, WSL/Docker report unavailable off Windows. WHY the kills are not unit-tested: doing so would kill the user's real WSL/Docker/ports - actions are user-verified, only parsers are tested. SURFACES: CLI `enigma resources [wsl|docker|free-port PORT|kill PID]` (no sub = status; the explicit command IS the confirmation). Dashboard: a "Resources" tab (`#/resources` in VIEWS) + origin-guarded `GET/POST /api/resources` (status / `{op,value}` -> `{...result, status}`); buttons confirm via `askConfirm`. TUI: a "Resources" sideItem after "Claude usage" (so tui.hub.test.ts identity index is now `CATEGORIES.length + 5`) - a cursor over an action list (named actions, then ports, then processes) + a `renderRemoveConfirm` before `runResourceAction`. To add an action: extend `runResourceAction` + the three UIs. (enigma-cli 1.19.0, dashboard 0.1.35.)
- `enigma kill <target...>` is the verb people actually type, over the same destructive actions (`enigma resources <action>` stays). One PURE grammar function, `parseKillTarget(token)` (tested, no spawning), decides what a target IS: `wsl|vmmem|vmmemwsl` -> wsl, `docker|docker-desktop` -> docker, `pid:N`/`pid N` -> pid, `:N`/`port:N`/`port N` -> port, a BARE number -> port when <= 65535 (that is what `enigma kill 3000` means) and a pid above it (no port can be), anything else -> a process name. `killTarget()` runs one; the CLI (`runKillCli`) joins the two-word `pid 1234`/`port 3000` forms into one token before parsing, loops over several targets, and prints usage + the listening ports when given none. NEW capability: `killByName` - exact name wins (`.exe` optional both ways), a substring only when it resolves to ONE program (else it lists up to 8 of the matches and refuses; "s" matched 135). SAFETY, all in the engine so every caller gets it - `killRefusalReason(pid, name)` is the ONE rule and `killPid` (the primitive every surface reaches a kill through, `freePort` and the dashboard/TUI included) applies it, so no route can reach a protected process; `freePort` resolves the port's owners from the UNCAPPED `allPorts()` (`listPorts`' limit is a display cap - filtering after the slice lost high ports) and skips + names the protected owners instead of killing them, because the low Windows ports belong to `System`/RPC. The rule: a per-platform `PROTECTED` regex (`isProtectedProcess`) refuses the kernel/session processes (Windows `system|secure system|registry|smss|csrss|wininit|winlogon|services|lsass|lsaiso|svchost|dwm|fontdrvhost|memory compression`; POSIX `init|systemd*|launchd|kernel_task|kthreadd` - the lists differ because `dwm` is fatal on Windows and an ordinary window manager on Linux), plus `process.pid`/`process.ppid` (killing enigma or its shell reads as a crash). The bare-number PID hint is offered only when that pid is NOT protected, so nothing is suggested that the next command would refuse. Typing the command is still the confirmation; nothing was added to `runResourceAction`, so the dashboard/TUI are untouched. (enigma-cli 1.48.0.)

- BULK GUARD on `killByName`: WHY it exists - manually testing `enigma kill node` on a real dev machine matched and force-killed 46 running `node.exe` processes (editor language servers, extension hosts, other tooling) in one shot, because `PROTECTED` only covers system/enigma/shell processes, never "this is someone's dev tool". Past `KILL_BY_NAME_BULK_LIMIT` (5) killable matches, `killByName` refuses instead of killing and names the count + how to proceed (one pid via `enigma kill pid <n>`, or repeat with `--yes`/`-y`). `killTarget`/`killByName` both take an `opts: { yes?: boolean }` (default off); `runKillCli` forwards the already-parsed `-y`/`--yes` global flag - no new CLI flag was added. `runResourceAction` and the dashboard/TUI kill-by-pid path are untouched (they never went through `killByName`).
