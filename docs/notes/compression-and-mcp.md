# Context compression engine + MCP (native, dependency-free)

- `src/compress/` is a native TypeScript port of the BEST of the headroom optimization engine (study clone at `references/repos/headroom`, Apache-2.0; the user owns the source account). It is NOT a 1:1 port of headroom's ~36k-LOC Rust core - only the high-value, self-contained subset, Node-builtins only (enigma has zero runtime deps, so NO `@modelcontextprotocol/sdk` and NO tokenizer/ONNX/embedding deps). DELIBERATELY UN-BRANDED per user instruction: no "headroom" name anywhere user-facing - everything is enigma-native (`enigma compress`, `enigma mcp`, tools `enigma_compress/retrieve/stats`, marker `<<enigma:ccr:HASH N_rows_offloaded>>`). Modules: `tokens.ts` (~4 chars/token estimate), `detect.ts` (heuristic content type: json confirmed by parse, plus log/diff/code/markdown/text - the Magika ML detector is intentionally NOT ported), `crusher.ts` (SmartCrusher: statistical JSON-array crush - per-field type/uniqueness/anomaly analysis, crushability gate `maxUniq<0.3 || hasSignal` with the safety carve-out that unique-entities-with-no-signal are left intact, keep-set = head/tail anchors + error rows + numeric anomalies(>2 sigma) + structural outliers + dedup + stride fill capped at maxItems=15), `logs.ts` (template-collapse repeated lines, keep error/warn verbatim), `text.ts` (head+tail truncation; code/diff/markdown pass through - no safe lossy transform without a parser), `ccr.ts` (Compress-Cache-Retrieve: reversible file-per-hash store under `~/.enigma/ccr`, sha256 12-char key, newest-500 retention cap, `stats.json`), `index.ts` (universal `compress()`: detect -> route -> if lossy store original + append CCR marker -> CompressResult). Paths resolve `homedir()` LAZILY per call so tests can point HOME/USERPROFILE elsewhere (`tests/compress.test.ts`).
- COMMAND-AWARE OUTPUT FILTERS (`shell.ts` + `shell-filters.ts`), ported from the RTK engine of the OmniRoute gateway (study clone at `references/repos/OmniRoute`, MIT; gitignored). UN-BRANDED like the headroom port: no "RTK"/"OmniRoute" name anywhere user-facing, and the markers are enigma's own (`... (N lines elided)`, `... (N identical lines elided)`, `... (N more similar lines)`), not `[rtk:truncated]`. WHAT IT ADDS over the generic compressors: they read structure out of the content, this reads the COMMAND that produced it. `npm install` prints a thousand progress lines and one error; `vitest` prints every passing test and one failing suite - nothing in the text itself says which lines matter, and the command does. `shell-filters.ts` is 55 filter packs as TYPED TS DATA, not JSON on disk: the compiled Bun binary cannot read on-disk assets (see monorepo-and-distribution.md), and as code they ship inside it with the type checker as their schema, so the zod validator and the ReDoS guard the source needed for user-supplied filters are both unnecessary here. Per filter: `commands`/`patterns` (how it is selected), `keep`/`drop`/`collapse` (which lines carry the signal), `anchor` (lines that survive truncation wherever they sit - the one line saying WHY the build failed is usually in the middle, which is what makes this different from a head+tail cut), `verdicts` (replace the whole output with one line when a pattern proves the run was clean), `dedupe`, `maxLines`/`headLines`/`tailLines`, `onEmpty`.
- TWO PRECISION FIXES THE PORT NEEDED, both found by the test suite rather than reasoned out. (1) SHAPE MATCHING NEEDS CORROBORATION. The upstream selects a filter when ANY ONE of its `patterns` matches the text; the GitHub CLI filter carries `X\s+\S+`, which every second sentence of English prose satisfies, so 40 lines of prose were being filtered by gh's rules. A filter applied to content it was not written for is the ONE way this engine can destroy meaning, so `SHAPE_MATCHES = 2` - two independent patterns of the same filter have to hit - and shape matching never reaches the `generic-output` fallback, which is command-only. An explicit `command` still decides outright. (2) A VERDICT IS NOT A SIZE HEURISTIC. The first cut gated the whole engine behind a minimum line count, which meant a three-line clean `vite build` never reached its `✓ built in` verdict and stayed three lines. Verdicts now run BEFORE any size gate, and the gate itself is gone - `compress()` already refuses inputs under 100 chars, so a second threshold only cost correctness (`uv sync`'s two-line clean run collapses to `uv: ok` through `onEmpty` for the same reason).
- THE THIRD FIX, AND THE ONE THAT CHANGES THE SHAPE OF THE ENGINE: `ALWAYS_KEEP`. A filter's `keep` list is a WHITELIST, so whatever its author did not foresee vanishes silently - and what gets forgotten is exactly the line worth keeping. Found by running a real failed `npm install` through it: the npm filter's list was written against npm 8's `ERR!`, npm 9 renamed that to `npm error`, and 124 lines compressed to two deprecation warnings with the ERESOLVE failure GONE at a triumphant 98%. Patching that one filter would have been whack-a-mole across 55 whitelists, so the guard is engine-wide: one narrow regex (`ERR!`, `error:`/`error `, `fatal:`, `panic:`, python tracebacks, `*Exception`, `FAIL/FAILED`, segfaults, `N vulnerabilities`) that no `keep` list can drop and that is always an anchor in truncation. It overrides `keep` (an OMISSION) but never `drop` (a DELIBERATE exclusion) - that split is the whole design. Cost of a false positive is a slightly longer output; cost of a false negative is a failure the model never sees, so the asymmetry decides it. `tests/shell-compress.test.ts` pins nine error dialects through the npm filter, which whitelists none of them.
- ROUTING (`index.ts`): `CompressOptions.command` is the shell command behind the input. `matchShellFilter` runs FIRST and its hit becomes content type `"shell"`; an explicit `opts.type` outranks it (`detect()` never returns `"shell"` on its own - command output is identified by its command, not its shape). `CompressResult.filter` carries the filter id so the CLI can report `shell:git-log` rather than just `shell`. Surfaces: `enigma compress --command "<cmd>"` and the MCP tool's optional `command` argument. MEASURED: 40 real commits of `git log` = 7041 -> 1619 tokens (77%), restored byte-identical through CCR.
- TESTS (`tests/shell-compress.test.ts` + `tests/fixtures/shell-output.json`): the 64 inline test cases the upstream filter packs carry were extracted as fixtures - one real output sample per filter plus the lines that must still be readable afterwards. The assertion is deliberately NOT byte-equality with the upstream's output (the pipeline differs - grouping was added, the markers are enigma's): it is that every line the upstream deemed essential SURVIVES, which is the property that actually matters and the one that catches a filter regression. Plus: every filter's patterns compile, no filter blanks output its keep patterns miss, prose with no command is never treated as command output.
- `src/mcp.ts` is a HAND-ROLLED stdio JSON-RPC 2.0 MCP server (no SDK). `handleMcpRequest(req, version)` is a PURE function (exported, unit-tested in `tests/mcp.test.ts` without real stdio); `runMcpServer` is the thin newline-delimited stdin/stdout loop. stdout is the protocol channel -> ALL diagnostics go to stderr, and `enigma mcp` is dispatched in cli.ts `run()` BEFORE any clack intro/parse noise (same early-dispatch slot as the hidden `__update-check`/`__lint-install`). Tools: `enigma_compress` (content + optional content_type -> compressed, carrying the CCR marker when lossy), `enigma_retrieve` (hash -> original), `enigma_stats`. Protocol version echoed from the client else `2025-06-18`; `notifications/*` get no reply.
- `enigma compress [file]` (`runCompressCli` in cli.ts): reads a file or stdin (`readFileSync(0)`), prints compressed to STDOUT and the savings line to STDERR (so output stays pipeable); `--retrieve <hash>`, `--stats`, `--type <t>` flags added to `parseArgs`/`CliOptions`. Both `compress` and `mcp` added to the `COMMANDS` set and `printHelp()`.
- DEPLOYMENT (`src/mcp-deploy.ts`) registers the MCP server in each managed agent's OWN config, gated by the `compress` toggle (config.ts `EnigmaConfig.compress`, default OFF/opt-in like `parallelSubagents` - adding an MCP server to a user's agents is a consent-worthy change). This is the "MIRROR SETTINGS" pattern (read-merge-write preserving other keys, mirror presence AND absence), NOT the verbatim command-copy pattern, because each agent uses a different file+format: claude `mcpServers.enigma` in `~/.claude.json` (global) / `.mcp.json` (local) / `<accountDir>/.claude.json`; codex `[mcp_servers.enigma]` TOML in `~/.codex/config.toml` / account `config.toml` (NO project-local - local scope is a no-op, matching commands); opencode `mcp.enigma` JSON in `~/.config/opencode/opencode.json` / `./opencode.json` / `<accountDir>/xdg-config/opencode/opencode.json`. SAFETY: `applyJsonEntry` refuses to write a file it cannot parse (would clobber user data) and never creates a file just to remove an absent entry. Windows: claude+opencode spawn without a shell so they get a `cmd /c` wrapper; codex resolves `.cmd` via PATHEXT itself (no wrapper). The deploy command is `resolveBin("enigma") ?? "enigma"` + `["mcp"]`. Wired as the `applyMcpConfig` hook in `installSkills` (alongside `applyClaudeConfig`/`applyGhConfig`/`applyBypassConfig`/`applyLintConfig` - same side-effect shape, NOT shown in the plan preview, skipped on dry-run) and called inside `syncDeployed` (per agent+scope) and `syncAccount` (after `mirrorAccountSettings`). Tests: `tests/mcp-deploy.test.ts`.
- To add another compressor content-type: add a branch in `index.ts` routing + a module returning `{ compressed, offloaded }`; keep it reversible (offloaded>0 triggers the CCR store + marker). To add another MCP tool: extend the `TOOLS` array + `callTool` switch in `mcp.ts` (the schema is inline JSON Schema). The compiled-binary asset wiring needs NO change (no on-disk assets - the engine is bundled into the binary; `enigma mcp` runs inside it).
- SOURCE ATTRIBUTION: every compression is attributed to its origin so the dashboard can show WHICH app saved tokens. `recordStats(before, after, source?)` keeps a durable per-origin `bySource: Record<string, SourceStats>` in `stats.json` ALONGSIDE the grand totals (legacy stats files have no `bySource` - `readStats` merges it through, absent = un-attributed). The MCP server learns the origin from the `initialize` request's `clientInfo.name` (e.g. `claude-code`/`opencode`/`codex`): `handleMcpRequest` stays a PURE function with an added `source?` 3rd arg, while the stateful `runMcpServer` loop captures `clientNameOf(req)` once at initialize and threads it to every later `tools/call` (connection state belongs in the loop, not the pure handler). `compress(content, {source})` forwards it; the CLI (`runCompressCli`) tags `"cli"`; no source -> `"unknown"`. History points are NOT per-source (YAGNI - the bySource panel covers "which app"; a stacked time-chart was not requested). Dashboard renders a "Savings By Source" panel from `stats.bySource` with a `prettySource` map (claude-code->Claude Code, opencode->OpenCode, codex->Codex, cli->CLI; unknown clients show title-cased raw - always truthful).
- TOGGLE APPLIES IMMEDIATELY: `enigma config compress on/off` now deploys/removes the MCP at once (the on/off twin of `dashboard`'s `applyDashboardMode`), fixing "I turned it on but it's not registered". `applyCompressToggle(scope)` lives in `mcp-deploy.ts` (light: imports only util+config) and is called by a custom `setCompress` setting in `settings-registry.ts` - NOT `enigmaToggle`. It mirrors presence AND absence across the managed tools, but an ENABLE only touches an agent whose config file already EXISTS (never creates config for a tool the user does not use); a DISABLE is already a no-op on an absent file. WHY the file-exists guard not `hasDeployment`: keeps the logic in the light module - importing skills.ts (the deploy engine + accounts.ts) into the registry would violate "settings-registry stays cheap to load". Before this fix the MCP deployed only at `enigma install`/auto-sync, so toggling the config flag alone left `mcpServers.enigma` absent until the next launch via `enigma <tool>`.

## The browser server (`chrome-devtools`, toggle `browser`, default on)

`mcp-deploy.ts` now manages a LIST of servers (`SERVERS`), each behind its own toggle: the enigma server (compress/recall/codeGraph) and the Chrome DevTools MCP server, so any agent can open the app in a real Chrome, drive it and read console, network, performance traces and Lighthouse - testing a UI or speed claim without a separate pack. Pinned `chrome-devtools-mcp@1.10.1` (Apache-2.0) with `--isolated` (a throwaway profile, never the user's logins), `--no-usage-statistics` and `--no-performance-crux` (CrUX would send trace URLs to Google). On Windows, agents that spawn without a shell get `cmd /c npx ...`; Codex resolves `.cmd` itself. Verified with a real `claude -p` session on the exact deployed entry: it opened a local page and reported title, heading and console output. Adding a second Codex table exposed a fixed-point bug - each sync removed and re-appended its table, so with two tables the order flipped every run and every sync reported a change; tables are now replaced in place.

HEADLESS BY DEFAULT (`browserHeadless`, setting `browser-headless`, default on). The server opens a VISIBLE window unless given `--headless` (its `--help`: "Whether to run in headless (no UI) mode. [default: false]"), so every agent test popped Chrome onto the user's screen mid-work.

THE LAUNCHER (`src/browser-mcp.ts`, hidden command `enigma __browser-mcp`). Putting `--headless` in each agent's entry was not enough: on 2026-10-16 a Claude session started from a `~/.claude.json` whose entry had lost the flag (writer never identified; Claude Code itself rewrites that file from memory) and Chrome opened on screen again, and nothing ever closed the browser before the session ended - on Windows the `cmd /c npx` chain orphaned it even then. So the entry now names enigma's launcher (`browserInvocation` = `mcpInvocation(tool, platform, "__browser-mcp")`, node + `bin/enigma.mjs` on Windows), never the server's flags, and the launcher is a newline-delimited JSON-RPC stdio proxy that: (1) builds the `npx chrome-devtools-mcp` flags from enigma's config at start, so no stale entry can drop `--headless`; (2) after `BROWSER_IDLE_MS` (5 min) with no traffic and no call outstanding kills the server tree (`taskkill /T` on Windows; SIGTERM to the process group elsewhere, whose puppeteer handler closes the detached Chrome); the next request starts a fresh server and first replays the agent's recorded `initialize` (id `enigma-browser-reinit`, its response swallowed) and `notifications/initialized`, and prepends a note to the first tool result after the restart (the fresh server has no pages and its own "reconnected" flag is false in a new process, so without it the agent's old uids fail unexplained); a `notifications/cancelled` drops the call from the in-flight set (the server sends no response for it, so it would otherwise block the idle close forever); lines are decoded with a `StringDecoder` so a multi-byte character split across pipe chunks is not mangled; a notification while no server runs is dropped instead of starting one; (3) kills the tree when stdin closes or on SIGINT/SIGTERM/SIGHUP; (4) answers any call outstanding when the server dies with a -32603 error instead of leaving the agent waiting. The server relaunches a disconnected browser on its own (`BrowserManager.ensureBrowser` checks `browser.connected`), which is why killing it is safe. Tests: `tests/browser-mcp.test.ts` (fake server); verified against the real server + Chrome on Windows. Old npx entries are replaced on the next sync (`tests/mcp-deploy.test.ts`); the pack builtin goes through the same `browserInvocation`.

THE OTHER WAYS IN (2026-10-22). The launcher only governs the MCP server; agents kept reaching a browser around it. Four channels, each closed where it can be stopped deterministically:

- SHELL COMMANDS - `src/browser-guard.ts`, hidden command `enigma __browser-guard`, a Claude PreToolUse hook on Bash/PowerShell installed always (install, `syncDeployed`, account mirror) and reading `browserHeadless` at run time. It refuses a browser started without `--headless` (chrome/msedge/chromium/brave/firefox, directly, via `Start-Process`, `start`, `cmd /c start`), a URL or `.html` handed to the default browser (`start`, `Start-Process`, `explorer`, `rundll32 url.dll`, `open`, `xdg-open`, `python -m webbrowser`, `gh --web`, `gh browse`), and headed tools (`playwright test --headed|--ui|--debug`, `show-report`, `codegen`, `PWDEBUG`, `cypress open`, `lighthouse` without headless chrome-flags, `--open`, `storybook dev`, `vitest --ui`, `ng serve -o`). Only the program a segment RUNS is judged (`taskkill /IM chrome.exe`, `grep chrome` pass) and heredoc/here-string bodies are dropped first. COST, measured on Windows: one `enigma` hook start is 0.9-4.3 s, so an unfiltered handler (one start per Bash call) was ruled out; the handlers carry `if` filters, and a real `claude -p` showed a plain command spawns none - but Claude Code runs EVERY handler of a command it cannot evaluate (anything with `$(...)`, `$VAR`, `$?`): 22 patterns meant 22 processes per such call. Hence 13 broad patterns (`*hrom*` = chrome/Chrome/chromium, `*irefox*`, `*rave*`, `*http*`, `*open*`, ...), with a test that every refused shape is reachable through one of them.
- SCRIPTS AN AGENT WRITES - guardrail `proc-headed-browser` (BLOCK, post-edit, scratchpad included): `headless: false` / `headless=False`. Puppeteer and Playwright default to headless, so turning it off is the one file-local signal. Escape: `enigma:allow-headed-browser`.
- STALE PROJECT ENTRIES - a project's `.mcp.json` / `opencode.json` / `.kimi-code/mcp.json` wins over the global entry, and one an older enigma wrote with `enigma install --local` started `cmd /c npx chrome-devtools-mcp` itself: frozen flags, never idle-closed, orphaned on Windows. Found live: a Claude session in a project with such an entry had a Chrome running under `cmd /c npx` with no launcher in its parent chain. `repairProjectBrowserEntries` (mcp-deploy.ts), run from `syncDeployed`, repoints every `chrome-devtools` entry carrying the flag set old enigma wrote (`chrome-devtools-mcp` with `--isolated --no-usage-statistics --no-performance-crux`, no `__browser-mcp`) in every project the Claude configs list. A team's own entry (any other args, often committed) and other servers are not touched, and with the `browser` setting off it writes nothing: it repoints, it never removes.
- ENIGMA ITSELF - `openUrl` (issue.ts) does nothing inside an agent's tool call (`CLAUDECODE=1`), so an agent checking its work with `enigma dashboard` no longer opens a tab in the user's browser; the URL is printed.

And the leftovers sweep now also knows Playwright's temp profile (`playwright_chromiumdev_profile-*`), so a script that crashed before `browser.close()` is reaped after the idle limit like the MCP server's browser. A browser with a window is NOT killed on sight: the user's own `playwright test --headed` in a terminal looks identical.
