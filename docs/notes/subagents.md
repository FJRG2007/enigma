# Subagent budget and compact window

`src/subagents.ts` (hook runtime) and `src/subagent-deploy.ts` (wiring). Settings: `subagent-limit` (default 2, per project with `-l`), `compact-window` (default 400k, global only) and `subagent-turns` (default 60, global only).

- WHY. Measured on one user's transcripts: a project burned a weekly plan limit in under three days. 87% of its model calls came from subagents - 136 of them in four days, each running 200-1,200 calls with a 400-550k context, because Opus/Sonnet 5.x run a 1M window natively and a session compacted only near 967k. Every call re-reads the whole context, so calls x context is the bill. The kernel's `parallel-subagents` prose (off by default) and the user saying "stop creating so many subagents" changed nothing; a refusal at launch does.
- THE LIMIT is a PreToolUse hook on `Agent|Task` (`enigma __subagent-hook pre`). Exit 2 with the reason on stderr refuses the call and the model reads the reason as the tool result - verified end to end with `claude -p`: two parallel launches under limit 1, one admitted, one refused with enigma's message. A subagent's own tool calls carry `agent_id` in the payload (and the main thread's never do), which is how nesting is refused; `session_id` is the parent's in all three events, so one directory counts the whole session.
- THE COUNT IS LOCK-FREE: one empty file per running subagent (`run-<agent_id>`, SubagentStart/SubagentStop) and per admitted-but-not-started launch (`pend-<tool_use_id>`) under `~/.enigma/subagents/<session>/`. Parallel Agent calls fire every PreToolUse before any SubagentStart, so the pending files are what make them count against each other; each hook writes its own, lists the directory and admits itself only within the first free slots in (mtime, name) order. Stale files expire (pending 2 min, running 6 h) so a crashed session cannot hold slots forever.
- SubagentStart answers with `additionalContext`: a five-line brief (one task, small tool output, scripted batch edits, no subagents). The subagent inherits none of the main conversation, and the waste was inside the subagents.
- THE COMPACT WINDOW is Claude Code's `autoCompactWindow` setting (tokens, 100k-1M, per settings file; `modelSettings` can scope it per model but the main and subagent model are the same canonical name, so it cannot single out subagents). It is written into the default account's settings.json and mirrored into managed accounts on sync. `auto` (0) leaves the file alone rather than deleting a value the user set, and install/sync never replace an `autoCompactWindow` already in the file unless `compact-window` is set explicitly in an enigma config file.
- The hooks are installed whatever the limit, since a project can set one while the global value is off; the cost is a process start per launch.
- THE TURN CAP (`subagent-turns`). Measured after the 400k window shipped (12 subagent transcripts, 2026-10): 60-655 calls and 8-137M input tokens per subagent, compacting at ~367k and carrying on. Compaction cuts the price of a call, never the number of calls, and four of those in parallel is what one user saw burn. Levers ruled out: no per-subagent token or compaction setting exists (`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` and `autoCompactWindow` hit the main thread too); the Agent tool takes no turn parameter; a PreToolUse hook on every tool costs a process start per call (2.5-15 s measured on this machine). What works at zero per-call cost: `maxTurns` in an agent definition, plus a user-level agent named `general-purpose` overriding the built-in. Both verified with `claude -p` on 2.1.296 - the override's prompt answered, and a six-step sequential task under `maxTurns: 2` stopped after two turns and was handed back (the parent can resume it with SendMessage, which gets a fresh set of turns on the same context).
- The override is `agents/general-purpose.md` beside each settings.json enigma manages, carrying `# enigma-managed: subagent-turns` in its frontmatter. Without that marker the file is the user's and is never rewritten or deleted; `off` deletes only enigma's. Its description is the built-in's so routing does not change; it sets no `tools` or `model`, so it inherits both like the built-in. Explore and Plan are not overridden: read-only, and their built-in definitions pin a model and tool list enigma cannot source.
- The default limit dropped from 4 to 2 with the turn cap: the bill is per running subagent, so concurrency multiplies it.
