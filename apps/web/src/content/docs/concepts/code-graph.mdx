Codebase memory gives your agents a **structural map of your code**: a persistent knowledge graph of functions, classes, call chains, imports, HTTP routes, and cross-service links, queryable in under a millisecond. It is powered by [codebase-memory-mcp](https://github.com/DeusData/codebase-memory-mcp) (MIT), a zero-dependency code-intelligence engine that parses 158 languages via tree-sitter.

This is **structural** memory of your code - complementary to [Recall](/docs/concepts/recall), which is **session** memory of what you did. It is **off by default**; everything is processed locally and your code never leaves your machine.

## How enigma integrates it

enigma does not reimplement the engine (it is a pure-C binary with vendored grammars and bundled embeddings). Instead enigma **manages** it: turning the setting on registers the server in each of your managed agents' MCP config so they gain its code-intelligence tools, and the enigma dashboard surfaces the graph. The binary is fetched on demand via `npx` (the package's own runtime) the first time an agent uses it - nothing to install up front.

## Enable it

<Cmd name="enigma config code-graph on" ex={["enigma config code-graph on"]}>
Register the codebase-memory-mcp server in your managed agents (Claude Code, Codex, OpenCode). Restart the agent to load it, then tell it "Index this project".
</Cmd>

You can also toggle it from the dashboard's **Code graph** tab, which shows your indexed projects and each project's architecture and graph schema.

## Use it

<Cmd name="enigma codegraph [action]" ex={["enigma codegraph status", "enigma codegraph on", "enigma codegraph projects", "enigma codegraph arch", "enigma codegraph off"]}>
`status` shows whether it's registered and available; `on`/`off` register or remove the MCP server across your agents; `projects` lists indexed projects; `arch [project]` prints a project's architecture overview. Any other action (e.g. `install`, `update`, `index`) is passed through to the underlying tool.
</Cmd>

Once it's on, your agent can query the graph directly over MCP - searching symbols, tracing call chains, mapping change impact, detecting dead code, and running Cypher-like queries - which typically replaces dozens of grep/read cycles with a single structural query.

## Privacy

The engine runs entirely locally and stores its graph under your cache directory. enigma only writes the MCP server entry into your agents' config (and removes it when you turn the setting off); the dashboard reads the graph through the tool's own local CLI, never over the network.
